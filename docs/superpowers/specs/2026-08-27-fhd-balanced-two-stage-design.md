# 1080p 平衡二采设计

## 目标

提升“质量优先二采样”在精确 1080p 目标下的真实细节，同时保留现有 4+4/4+5 训练型二采加速、15 秒时长支持、单 MP4 音视频输出和导演台布局。

## 问题

当前 32GB 档位为 1080p 规划 `1280x704 -> 1920x1056 -> RTX VSR 1920x1080`。最后一步仅改变少量边缘尺寸，几乎不增加可见细节，还可能造成非等比拉伸。清晰度上限主要来自首采网格，而不是 MP4 码率。

## 方案

仅当性能模式为 `quality_two_stage`、预算档位为标准质量且最终目标精确为横向或竖向 FHD 时启用：

- 横向：`1344x768 -> 2016x1152 -> 中心等比裁切 -> Lanczos 1920x1080`
- 竖向：`768x1344 -> 1152x2016 -> 中心等比裁切 -> Lanczos 1080x1920`
- 保留现有 FL 4+4 和 Reference 4+5 采样契约，不增加采样步数。
- 最终阶段不初始化 RTX VSR，不依赖 NVIDIA Video Effects 能力。
- 逐小批次在 CPU 完成裁切和缩小，不创建整段 1080p 副本。
- 原音频继续交给现有 DaSiWa/FFmpeg 合成，只保存一个 MP4。

## 隔离边界

- 2K、4K、低显存二采和普通性能模式保持原路由。
- 普通 `downscale`、用户主动选择的 Lanczos、AI 超分和 RTX VSR 行为不变。
- 若训练型二采依赖或显存预算失败，仍在采样前明确失败或按现有回退契约处理。
- 导演台不新增控件、不调整节点尺寸，只在中文 warning/API 元数据中声明实际链路。

## 验收

- 32GB、15 秒、1920x1080 得到 `1344x768 -> 2016x1152` 并解析为专用等比 Lanczos 缩小。
- 1080x1920 得到对应竖向尺寸。
- 该路由不调用 RTX VSR 前置检查。
- 2560x1440 仍保持当前规划及 RTX VSR 路由。
- 输出尺寸、帧数、音频和单 MP4 合成契约不变。
