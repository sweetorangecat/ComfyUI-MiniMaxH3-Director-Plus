# 全模式免费智能 1080p 与素材安全移除设计

## 目标

为 U11 Director Plus 提供一套默认无需付费服务的自动路线：根据 H3 模式、实际后端和可用显存选择可靠的加速方式，生成后只执行一次本地 AI 超分，并保证最终输出至少达到对应画幅的 1080p 级尺寸。同时补齐导演台上传素材的安全移除能力。

成功标准：

- T2VA、I2VA、L2VA、FL2VA、REF2VA 和音色参考路线均有兼容的加速与免费 1080p 输出方案。
- 横屏输出至少为 `1920×1080`，竖屏至少为 `1080×1920`，其他画幅保持比例且短边至少为 `1080`。
- 每次只运行一个超分器，不串联 RTX VSR、RealESRGAN、锐化或第二个超分模型。
- 低显存设备以限制时长换取 1080p，超限时在排队前明确阻止并说明原因。
- REF2VA 不再暴露已实测灰屏或明显软化的性能组合。
- 用户可以从导演台清空已上传的图片和音频引用，但不会删除 ComfyUI `input` 目录中的原文件。

## 非目标

- 不承诺 H3 原生 1080p、2K、4K 或 60 FPS。
- 不通过提示词伪装分辨率、超分、插帧或编码能力。
- 不自动删除用户素材文件。
- 不自动改写用户提示词中的 `<Picture N>` 或 `<Audio N>`。
- 不在本次工作中恢复 REF2VA 训练型 latent 二采；它需要独立的端到端视觉验证。
- 不默认启用 RIFE 插帧。

## 方案比较与选择

### 方案 A：所有模式使用官方 4 步并超分

速度最快，但 REF2VA 的人物身份、服装细节和多参考约束更容易损失。超分无法恢复采样阶段已经丢失的语义结构，因此不作为统一默认方案。

### 方案 B：所有模式使用 20 步 Sage 并超分

质量稳定，但基础模式没有充分利用已验证的官方 Turbo，整体速度收益偏低。

### 方案 C：按实际后端自动选择并统一免费超分

采用此方案。基础端点后端使用官方 Turbo；REF2VA 后端使用 20 步 SageAttention；所有正常结果再使用一次本地 RealESRGAN X2。它在速度、参考一致性、稳定性和免费约束之间最均衡。

## 路由设计

### 标准显存路线

| 用户模式 | 实际后端 | 生成加速 | 禁用能力 | 最终处理 |
|---|---|---|---|---|
| T2VA | `fl2va_model` | 官方 Turbo 4 步；T2VA 不使用 EasyCache | 社区 v4 不兼容路线、latent 二采串联 | RealESRGAN X2 一次 |
| I2VA | `fl2va_model` | 官方 Turbo 4 步，保留硬首帧 | EasyCache、重复超分 | RealESRGAN X2 一次 |
| L2VA | `fl2va_model` | 官方 Turbo 4 步，保留硬尾帧 | EasyCache、重复超分 | RealESRGAN X2 一次 |
| FL2VA | `fl2va_model` | 官方 Turbo 4 步，保留硬首尾帧 | EasyCache、重复超分 | RealESRGAN X2 一次 |
| REF2VA | `ref2va_model` | 原生 20 步 + SageAttention | 质量优先二采、低显存 reference latent 二采、参考图加速 EasyCache | RealESRGAN X2 一次 |
| 任意模式 + H3 音色/Fish | `ref2va_model` | 与 REF2VA 相同 | 训练型二采、EasyCache | RealESRGAN X2 一次 |

`resolved_backend` 是最终性能路由的唯一依据。前端模式名称不得直接选择不匹配的 LoRA。

### 免费超分策略

默认模型为本地 `RealESRGAN_x2plus.pth`，允许使用现有模型自动解析机制定位文件。若模型缺失，应在生成前给出安装提示，不得静默切换到付费服务。

处理顺序：

1. 以 H3 合理的原生像素预算完成采样和 VAE 解码。
2. 检查帧张量有效、尺寸合法且不存在 NaN/Inf 或近乎纯色的结构性失败。
3. 逐帧执行一次 X2 AI 超分。
4. 按目标画幅中心裁切或等比缩小到最终尺寸。
5. 以 H.264/MP4 保存一次，保留原始音频和时长。

目标尺寸规则：

- `16:9`：`1920×1080`。
- `9:16`：`1080×1920`。
- `1:1`：`1080×1080`。
- 其他比例：保持请求比例，将短边设为至少 `1080`，尺寸对齐编码器所需偶数。

超分器输出若已达到或超过目标，只允许等比缩小或轻量裁切，不再调用另一种重建器。RIFE 默认为关闭。

## 低显存 1080p 设计

低显存路线遵循“限制时长、降低首采网格、阶段间卸载、最终一次 X2 重建”的原则。显存判断同时考虑显卡总容量和排队前可用显存；不能把总容量当作当前空闲容量。

### 第一阶段安全合同

| 显存状态 | 时长合同 | 行为 |
|---|---|---|
| 低于最低安全预算 | 不允许排队 | 提示关闭其他任务、等待模型卸载或重启 ComfyUI |
| 8GB 级且达到安全空闲预算 | 推荐 4 秒，最多 6 秒 | 依据时长降低首采网格，阶段间释放模型，最终 X2 到 1080p |
| 12–16GB 级且达到安全空闲预算 | 最多 6 秒 | 使用较高首采网格，最终 X2 到 1080p |
| 16GB 以上 | 先沿用 6 秒上限 | 只有端到端显存回归证明安全后才分档放宽 |

不凭理论直接开放 8 秒以上。后续放宽必须以真实工作流峰值显存、完整 MP4 输出和连续多次运行为依据。

### 模式差异

- T2VA、I2VA、L2VA、FL2VA 可以使用现有低显存训练型二采路线。
- REF2VA 和所有 `ref2va_model` 路线不得进入当前 `trained_latent_ref`，因为生产样本已出现灰屏。它们改用低显存采样策略，再执行单次逐帧 RealESRGAN X2。
- Fish 音色锁定始终按 REF2VA 安全路线处理，不叠加训练型二采。

### 用户提示与阻止规则

选择低显存 1080p 时立即显示：

> 已启用低显存 1080p 模式。当前显存档位最多支持 6 秒；系统会降低生成阶段分辨率，并在生成后免费超分到目标 1080p 尺寸。

排队前再次校验实际空闲显存和时长。超过上限时直接阻止，并返回：总显存、当前空闲显存、请求时长、允许时长以及“缩短时长或拆成多段”的处理建议。不得静默降低最终尺寸或关闭超分。

## 结构性失败保护

超分前增加廉价、确定性的安全检查：

- 帧张量必须为有限数值并具有合法通道和尺寸。
- 视频不得是全零、近乎常量或完全无动态范围的输出。
- 不以低饱和度单独判定失败，因为合法场景可能是黑白或低饱和风格。
- 检查失败时保存必要诊断信息但不执行超分，向用户提示“生成阶段输出无效，请重新生成”。

人物相似度、服装一致性等主观质量不能由简单阈值可靠判断，因此不做自动重试或静默换预设。

## 性能预设与兼容性收口

新增统一入口“免费智能 1080p”。导演台内部根据 `resolved_backend`、显存和时长解析真实路线。

REF2VA 允许的生产预设收敛为：

- 稳定质量。
- 质量优先加速（20 步 Sage，无 EasyCache）。
- 参考高清（原生 20 步）。
- 参考极速（官方 4 步），仅作为用户主动选择的速度优先选项。
- 低显存安全路线。

REF2VA 默认隐藏或拒绝：

- 质量优先二采样。
- 低显存 reference latent 二采。
- 参考图加速（6 步 + EasyCache）。
- 不匹配的 FL/community v4 LoRA。

旧工作流若传入被禁用组合，后端必须回退到对应后端的安全预设并记录明确 warning；前端隐藏不能代替后端校验。

## 上传素材安全移除

### 行为定义

每个空槽位显示“选择文件”。每个已有素材的槽位显示“更换”和“移除”。

“移除”执行以下动作：

1. 将对应隐藏 ComfyUI widget 的值设为空字符串。
2. 调用原 widget callback，使序列化状态和 API prompt 同步更新。
3. 移除图片或音频预览。
4. 恢复“未上传”占位文案。
5. 标记画布为已修改。

它只取消当前节点引用，不调用删除 API，不删除 `input` 目录文件，也不修改其他工作流。

### REF2VA 中间槽位

移除中间参考图时，后续参考图自动向前补位，确保物理槽位连续。补位后显示：

> 参考图已重新编号，请检查提示词中的 `<Picture N>` 引用。

系统不自动改写提示词，因为文本中的 Picture 可能绑定人物、场景或道具，机械替换可能改变语义。

### 音频槽位

移除中间音色参考时，后续音频、对应 `voice_reference_name_N` 和相关显示状态作为一个绑定单元向前补位。补位后提示检查 `<Audio N>` 和 `(Sx)` 绑定。

### 首尾帧槽位

I2VA、L2VA、FL2VA 的首帧和尾帧独立清空，不自动把普通参考图转换成端点。清空导致当前模式缺少必需端点时，导演台立即显示不可执行提示，并在排队前由后端再次阻止。

## 导演台边界修复

导演台 DOM 不再把根元素、DOM widget 和节点外框同时硬锁为相同的 `1350px`。节点外框保留稳定尺寸，内容区使用 `width: 100%`、`min-width: 0` 和 `max-width: 100%`，并为节点边框、端口和内边距预留空间。

高度采用固定可视区域加内部纵向滚动：DOM 申报高度必须与节点可用内容高度一致；上传预览、音色面板或提示词工具展开后只能在节点内部滚动，不得越过节点或覆盖下方节点。导演分组在节点四周保留可见间距，输出分组与导演分组之间保留独立沟槽。

布局测试不能继续只匹配固定宽度字符串。必须验证内容宽度不超过节点内部宽度、节点矩形位于所属 group 内、相邻 group 存在最小间距，并在 ComfyUI 真实浏览器中覆盖侧栏打开和约 53% 画布缩放的截图回归。

## 前后端数据流

```text
用户模式/显存/时长
  -> schema 过滤兼容预设
  -> director 解析 resolved_backend
  -> performance 选择安全加速路线
  -> VRAM 预算与时长门
  -> H3 采样与 VAE 解码
  -> 结构性失败检查
  -> 单次 RealESRGAN X2
  -> 画幅对齐与 H.264/MP4 输出
```

素材状态流：

```text
选择文件 -> 上传 -> widget 保存文件名 -> 预览
更换文件 -> 上传新文件 -> widget 替换 -> 更新预览
移除引用 -> widget 清空 -> 必要时压缩连续槽位 -> 删除预览 -> 保留磁盘文件
```

## 错误处理

- LoRA 不兼容或零 patch：回退到对应后端的安全原生/Sage 路线，不得继续少步数采样。
- 免费超分模型缺失：生成前报出准确模型名和安装位置，不调用付费服务。
- 可用显存不足：生成前阻止，报告真实空闲显存。
- 时长超出低显存合同：生成前阻止，不静默降低尺寸。
- REF2VA 被请求使用不安全二采：规范化为安全低显存路线并 warning。
- 删除中间素材后产生编号变化：自动压缩槽位并提示检查标签。
- 清空必需首尾帧：节点进入不可执行状态，保留用户其他素材。

## 测试设计

### 前端状态测试

- 空槽位只有“选择文件”。
- 上传后显示“更换”“移除”和预览。
- 移除后 widget 为空、callback 被调用、预览消失、画布变脏。
- REF2VA 删除中间图片后，后续文件连续前移。
- 音频移除时文件名和角色名同步前移。
- 清空首尾帧不会删除磁盘文件或调用后端删除接口。

### 路由与 schema 测试

- 每个模式解析到正确 `resolved_backend`。
- 基础模式的智能 1080p 使用官方 Turbo 和单次 X2。
- REF2VA 默认使用 20 步 Sage，并拒绝 EasyCache 与训练型二采。
- 旧的不安全 REF2VA 预设获得明确回退 warning。
- Fish 路线不能进入训练型二采。

### 显存与时长测试

- 8GB 级安全预算允许 4–6 秒，不允许 7 秒。
- 空闲显存不足时即使总显存足够也必须拒绝。
- 超限错误包含请求时长、允许时长和显存信息。
- 低显存 REF2VA 使用单采 + X2，不进入 `trained_latent_ref`。

### 输出测试

- 横屏、竖屏、方形和宽银幕目标尺寸正确。
- AI 超分只调用一次，达到目标后只缩小或裁切。
- 音频、帧数和时长保持不变。
- NaN、Inf、全零和近乎常量帧在超分前被拒绝。
- 合法低饱和视频不会因饱和度低被误拒绝。

### 真实验收

至少在基础后端和 REF2VA 后端各运行一段 4 秒与一段 6 秒视频，验证：峰值显存、最终尺寸、人物/端点一致性、无灰屏、无重复超分、音频保留和连续第二次运行不泄漏显存。低显存时长上限只有在此验收通过后才能提高。

## 文档与迁移

- 使用说明区分“生成阶段分辨率”和“最终 1080p 输出”。
- 故障排查说明低显存时长门、免费模型缺失和 REF2VA 禁用路线。
- API schema 返回按模式允许的性能预设与最终尺寸规则。
- 旧工作流保持可加载；不安全预设在运行时安全回退并提示，而不是破坏序列化字段。

## 实施边界

本设计可作为一个实施计划完成，但代码修改必须拆成可独立验证的阶段：

1. schema 与路由收口。
2. 免费智能 1080p 输出策略。
3. 低显存时长门与提示。
4. 上传素材安全移除及槽位压缩。
5. 前端几何修复与真实浏览器视觉回归（沿用已确认的导演台越界诊断）。
6. 文档、全量回归和真实 GPU 验收。
