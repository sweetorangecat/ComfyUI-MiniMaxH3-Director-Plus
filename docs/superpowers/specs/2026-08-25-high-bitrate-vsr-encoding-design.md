# 质量二采高码率 VSR 与高质量编码设计

## 背景

现有“质量优先二采样”已经使用训练型 latent 放大和第二阶段重绘，并在最终输出阶段通过 RTX VSR 达到 2K/4K 尺寸。当前生成链路已经稳定，但最终远景、云雾渐变和建筑细线仍会受到两处限制：RTX VSR 使用面向普通压缩源的 `ULTRA` 档，以及 H.264 使用 CRF 20 且没有明确的 BT.709 色彩标记。

## 目标

- 只增强“质量优先二采样 + RTX VSR”这一条已验证链路。
- 让干净的 H3 VAE 输出使用 NVIDIA `HIGHBITRATE_ULTRA`，避免对本来没有压缩噪声的帧进行过度伪影抑制。
- 将这条路线的最终 H.264 编码质量固定提升到 CRF 16。
- 无损写入 BT.709 limited-range 标记，避免播放器色彩解释不一致。
- 旧 U11 工作流无需手动连线，也无需用户重新选择控件。
- 导演台布局、其他性能模式、音频路径、帧率和最终尺寸行为保持不变。

## 方案选择

### A. 仅增强质量二采路线（采用）

为 RTX VSR 增加 `HIGHBITRATE_ULTRA` 公共质量值。只要性能预设解析为 `quality_two_stage` 且最终输出为 `rtx_vsr`，旧工作流保存的 `HIGH`/`ULTRA` 都自动迁移到 `HIGHBITRATE_ULTRA`。导演台继续使用原位置的 RTX VSR 质量控件，并在该性能预设下只展示兼容档位。

最终输出节点只在同一路线把 CRF 上限收紧到 16；如果调用者已经指定 0–15，则保留更高质量值。H.264/MP4 编码完成后通过 FFmpeg `h264_metadata` 位流过滤器进行 stream-copy，写入 BT.709 limited-range VUI。这个步骤不重新编码视频或音频；失败时保留已经成功生成的视频并打印明确警告。

### B. 所有模式统一使用高码率 VSR 和 CRF 16（不采用）

普通极速或低显存输出可能仍含明显生成噪声或压缩样伪影，高码率 VSR 不一定适合；全局 CRF 16 还会显著增加所有输出文件大小，变更范围过大。

### C. 新增独立编码高级面板（不采用）

虽然可让用户手动选择 CRF、色彩空间和高码率 VSR，但会改变导演台界面并暴露容易组合错误的选项，不符合现阶段保持 UI 稳定的要求。

## 请求与兼容规则

- `rtx_quality` 允许值扩展为 `HIGH`、`ULTRA`、`HIGHBITRATE_ULTRA`。
- `quality_two_stage + rtx_vsr` 的实际质量固定解析为 `HIGHBITRATE_ULTRA`。
- 其他性能预设保持用户所选 `HIGH` 或 `ULTRA`；也不自动改变现有编码质量。
- 公共 schema 增加按性能预设划分的 RTX 质量兼容表。
- 前置检查必须使用“实际解析后的质量”，确保不支持该能力时在 H3 采样前报错。
- API 和工作流元数据同时记录请求值与实际值，便于服务器排查。

## 输出编码

- `quality_two_stage + rtx_vsr + H.264`：实际 CRF 为 `min(用户值, 16)`。
- 其他路线：保持原 `quality` 输入。
- 工作流和 API 模板的可见默认值改为 16，使界面与实际编码一致。
- H.264 输出完成后以 stream-copy 写入：limited range、BT.709 primaries、BT.709 transfer、BT.709 matrix。
- BT.709 标记步骤沿用原音频、容器元数据和 ComfyUI 元数据，不改变帧数、FPS、分辨率或音频轨道。

## 错误处理

- SDK 不包含 `HIGHBITRATE_ULTRA` 时，由现有 RTX VSR 前置检查在生成开始前给出中文错误。
- 编码失败仍按现有规则报错，不生成伪成功结果。
- BT.709 无损标记失败不删除已编码成品，只记录包含 FFmpeg 错误的警告。
- 临时文件只创建在最终文件同目录；成功后原子替换，失败后清理临时文件。

## 验证

- schema、导演节点、前端和 API 模板测试覆盖新质量值及旧值迁移。
- RTX VSR 单元测试覆盖枚举解析和不支持能力的早期错误。
- 输出节点测试覆盖：质量二采使用 CRF 16、其他模式保持 CRF 20、H.264 BT.709 stream-copy 命令、失败保留原文件。
- 工作流构建测试确认唯一 U11 JSON 的输出质量为 16、二采自动连接不变。
- 运行完整测试、Python 编译检查、工作流结构校验，并确认本地主分支和远程 `main` 一致。
