# 按目标尺寸执行 VOSR2

用户要求最终尺寸至少达到所选档位，由内部计算倍率，不增加普通页面的技术选项。此前授权的实现、提交和推送继续有效；具体实现由本次授权交由开发者判断。

## 设计

按实际解码帧计算 `max(1, target_width/source_width, target_height/source_height)`，两轴向上取偶数以兼容编码。使用整数分数运算避免浮点边界误差；只在输出入口计算一次，后续适配器复用已解析的画布，避免再次按比例取整而扩大。输入已经超过目标时保留尺寸；所有路径都不先缩小输入。

当前 TE-Speed-VOSR2 的公开节点接口是整数 scale。整数等比放大继续直接调用；小数倍率用 CPU float32 bicubic 等比放到必要尺寸，然后调用后端原生 scale=1 重建。后端在最终尺寸上执行模型，不是先跑 2x 再缩回。准备输入分块写入预分配缓冲，避免逐帧列表加拼接的额外峰值。保持一次整段后端调用，保留批处理、音频、帧数及采样时钟。

旧 QHD/UHD force_2x 不再缩小输入，新计划不再生成该标记。VOSR2 最终尺寸计算、编码尺寸和输出元数据统一。SeedVR2 的既有目标处理不在本次修改范围内。

执行记录区分源尺寸、有效倍率、后端整数倍率、重建输入尺寸和实际输出。后端返回不足尺寸或非有限像素时明确失败，不用普通插值伪装成成功超分。

普通页面只显示自动倍率说明；既有 VOSR2 实验配置移到默认收起的高级区域，保存值和工作流兼容性保留。不新增画质预设，不在未经目标 GPU 对比的情况下叠加采样优化。

## 验证

- 1344x768 到 1920x1080 计算为 1920x1098，竖屏对称；独立短边 1080 为 1890x1080。
- 超过目标、整数倍率、旧 force_2x、奇数边界、帧数和有限值校验。
- 通过真实输出适配器检查后端输入与编码/元数据尺寸。
- 本地 RTX 3070 上做短帧原生 VOSR2 验证；不访问远程 5090，不把本地验证当作 5090 性能证明。
