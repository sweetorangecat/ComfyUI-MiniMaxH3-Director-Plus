# H3 质量二采 RTX 轻度去模糊链设计

## 目标

服务端“质量优先二采样”输出 2K 时，保持现有训练型 H3 二采尺寸、LoRA、采样步数和显存预算不变，改善结构完整但纹理偏软的问题。不得把该处理扩散到低显存路线，也不得通过提高 H3 二采网格重新引入显存不足、灰屏或崩溃。

## 已确认现状

- 问题视频为 2560×1440、24 FPS、H.264/MP4，视频码率约 25.7 Mbps，编码不是清晰度瓶颈。
- 实际生成链为 1280×704 首采、1920×1056 训练型潜空间放大与二采、2560×1440 `HIGHBITRATE_ULTRA` RTX VSR。
- 相邻两次服务端任务使用相同二采路线、LoRA、步数、源尺寸、RTX 质量和编码质量；随机种子仍会造成生成细节差异。
- 1920×1056 与 2560×1440 的宽高比略有差异。NVIDIA 建议 VSR 输入输出保持相同宽高比以取得最佳质量。

## 选定方案

只在 `quality_two_stage` 且最终后处理为 `rtx_vsr` 时执行以下固定链路：

1. 将二采帧以中心裁切方式适配最终宽高比，不进行非等比拉伸；
2. 使用 NVIDIA VSR `DEBLUR_LOW` 在源尺寸做一次轻度去模糊；
3. 将结果交给现有 `HIGHBITRATE_ULTRA`，等比重建到最终尺寸；
4. 沿用现有逐帧流式处理、H.264 CRF 16 上限、BT.709 标记和原声音轨；
5. 不叠加 RIFE、RealESRGAN、OmniSR、Lanczos、额外锐化或降噪。

`DEBLUR_LOW` 只修复低到中等软化，不承担超分；`HIGHBITRATE_ULTRA` 继续承担最终尺寸重建。两个效果均保持在 GPU 上逐帧执行，输出及时转回 CPU 小块交给编码器，不保留完整 2K GPU 帧批次。

## 路线隔离

- `quality_two_stage + rtx_vsr`：启用 `DEBLUR_LOW -> HIGHBITRATE_ULTRA`。
- `low_vram_two_stage + ai_upscale`：保持 RealESRGAN X2 单路重建，不启用 NVIDIA 去模糊。
- 其他性能预设：保持现有后处理行为，不自动叠加去模糊。
- `motion_smoothing=rife_x2` 与训练型二采继续互斥。

导演台不增加新的控件，不改变现有布局；中文提示更新为“轻度去模糊 + 高码率 RTX VSR”。API 继续使用现有 `performance_preset=quality_two_stage`、`postprocess_mode=rtx_vsr` 和 `rtx_quality=HIGHBITRATE_ULTRA`，不新增必填入参。

## 前置检查与失败处理

在 H3 模型加载前，用真实 640×360 CUDA 测试帧依次验证：

1. `DEBLUR_LOW` 能以 640×360 输入并输出 640×360；
2. `HIGHBITRATE_ULTRA` 能接收去模糊结果并输出 1280×720；
3. 两个效果都能正常关闭和释放。

任一步失败都必须在 H3 生成开始前给出中文错误，明确失败的是“轻度去模糊”还是“高码率 RTX VSR”。运行中不得静默回退为普通 VSR、Lanczos 或原生直出，避免用户得到未声明的质量链路。

## 测试范围

- 质量二采解析为双效果链，低显存二采和其他预设保持单效果或原路线；
- 前置检查按同尺寸去模糊、再放大顺序运行并关闭两个处理器；
- 输入输出宽高比不同时先做中心裁切，裁切结果与目标比例一致且不发生拉伸；
- 逐帧输出保持帧数、顺序、音频、最终尺寸和 BT.709 标记；
- 任一 NVIDIA 效果创建、加载、运行或关闭失败时，错误在 H3 启动前暴露；
- 完整单元测试、工作流结构校验和 U11 唯一工作流重建通过。

## 非目标

- 不承诺随机种子之间具有相同的生成纹理；
- 不把 1920×1056 二采源描述成原生 2K；
- 不提高训练型二采空间网格或时长上限；
- 不新增第二份 U11 工作流；
- 不在本机启动 ComfyUI。
