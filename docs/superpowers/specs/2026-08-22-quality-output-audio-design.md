# U11 清晰度与音频输出修复设计

## 目标

修复“质量优先二采样”在 2K 输出时真实细节基础过低、RIFE 默认启用导致耗时和合成帧柔化、H3 音轨存在但几乎不可听的问题。保持单一 U11 工作流、中文导演台、自动连线和旧工作流控件顺序兼容。

## 已确认根因

- 当前 2K/15 秒质量二采链为 `960×544 首采 → 约 1440×832 latent 二采 → 2560×1440 RTX VSR`，首采只有约 0.52 MP。
- `motion_smoothing=auto` 会在质量二采 + RTX VSR 中自动变成 RIFE 2x，输出 723 帧并增加耗时；RIFE 不改变源偶数帧，但一半输出帧是合成帧。
- 问题视频包含 AAC 音轨，但平均约 -52.7 dB、峰值约 -31 dB；保存链没有输出响度修正。

## 设计

### 清晰度

质量二采的目标 RTX VSR 线性倍率由 1.9 收紧为 1.4。2K 16:9 因此选择约 0.83 MP（约 1248×704）首采，latent 二采后约 1888×1056，再以约 1.36 倍 RTX VSR 输出 2560×1440。4K 受 H3 官方 1344×768 上限约束，不突破模型原生画布。

不恢复整段 VideoVAE 解码、图像重绘、重编码路线，避免重新引入灰屏、内存暴涨和崩溃。

### 运动平滑

导演台只展示“关闭（推荐）”和“RIFE 2x（48 FPS）”，默认关闭。后端继续接受旧值 `auto`，但将其解析为关闭，避免旧 U11 自动加载 RIFE。RIFE 仍只允许 RTX VSR，低显存模式仍禁止。

### 音频

导演台新增末尾字段 `audio_loudness`，选项为 `auto` 与 `original`，默认 `auto`。自动模式在写入临时音频前对 ComfyUI AUDIO waveform 做峰值归一化：目标峰值 -1.5 dBFS，最大提升 30 dB；静音保持静音，过响音频会衰减。原始模式不改 waveform。

该字段追加在现有 widget 序列末尾，不移动 motion_smoothing、时间线、对白、角色名或媒体上传槽。

## API 与错误行为

- 公共 API 新增 `audio_loudness=auto|original`，默认 `auto`。
- `motion_smoothing` 默认改为 `off`；旧 `auto` 请求继续接受并解析为 `off`。
- 没有音轨时不执行归一化；非法响度模式在 H3 采样前拒绝。

## 验证

- 分辨率测试证明 2K 质量二采首采不低于 0.80 MP，二采后到 2K 的倍率不超过约 1.5。
- schema、导演台、API 与工作流测试证明 RIFE 默认关闭、旧 auto 关闭、音频控件追加在末尾。
- 音频单元测试覆盖低音量提升、过响衰减、静音、原始旁路和 combine 实际传值。
- 重建 U11 后校验节点、连线、子图、重叠和 widget 索引；执行完整测试与 JavaScript 语法检查。
