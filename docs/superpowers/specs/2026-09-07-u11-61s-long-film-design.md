# U11「61 秒长片（分段续拍）」设计

状态：设计稿，等待方案确认；本文件不表示界面或执行链已实现。

## 已确认的目标

用户要求独立的 61 秒档位，并同时交付具体提示词方案。沿用现有 U11；1080p 精修和普通单段生成保持兼容。长片目标为 24fps、1464 帧、61.000 秒视频；不依赖变速、补静帧或循环帧凑长。2K 指 2560×1440 或竖版 1440×2560 的最终输出目标，并非承诺原生单次 2K 推理。

## 项目取证（2026-09-07）

- nodes/schema.py、nodes/director.py 当前按单段 4–15 秒校验。
- nodes/guide.py 构造一次 H3 条件与初始 latent；现有采样/输出节点处理一个片段。
- api/routes.py 将单段 API 图交给 ComfyUI 标准队列，目前没有长片项目调度器。
- js/minimax_h3_director_plus_v9.js 是现有导演台入口。不能只新增下拉枚举，否则会让单段节点误采样 61 秒。
- 本地安装了 H3 Motion Context，但未安装 Herrgotts H3 Infinite。源码中存在视频与音频独立 denoise mask 参数；仍需真实能力探测，不能仅凭参数名称视为适配成功。
- 上一项工作接通了 1080p 二采后的 SeedVR2 3B 精修。长片可复用逐段精修，但原采样 latent 必须另存，不能拿放大后的 RGB 冒充原始续拍状态。

## 三种路线

1. 推荐：分段 AV latent 续拍，逐段存档与后处理，最后流式合成。可继承动作和声音；需要处理重叠、冻结尾部和净新增时长。
2. 独立短镜头剪辑：适合多场景短剧，镜头边界更好控制；不能声称同镜头连续运动或原生音色自动连续。
3. 单次 61 秒采样：不采用；现有预算与原生长度合同不支持，不能靠改上限绕过。

## 用户界面

- 增加「61 秒长片（分段续拍）」入口，内部键 long_film_61s。
- 选择后，总时长固定显示 61 秒，另显示预计故事段数和实际生成子段数。
- 全片设定：人物外观、服装、场景布局、画面风格、声音基线。
- 段落列表：全片起止时间、开场状态、本段动作、镜头、对白及时间、声音、结束状态。
- 提示词按钮：「插入 61 秒模板」「检查段落与时长」。自动拆段由确定性时间/边界规则负责，不假装本地存在能理解任意长文的 LLM。
- 已有结构化分段稿可导入；只有一整段散文时，要求补齐分段，不平均截字、不自动删改对白。
- 每段状态：待生成、生成中、已保存、精修中、完成、失败。操作为开始、停止后续、从失败段继续。
- 此档位有独立长片输出节点/任务路径，普通单段执行器收到 long_film_61s 必须明确拒绝误用。

## 时长合同

默认故事段为 [9,9,9,9,9,9,7] 秒，对应 [216,216,216,216,216,216,168] 帧，共 1464 帧。它是导演节拍模板，不代表底层始终只执行七次采样。

每个生成子段保存四种时间：全片可见区间、当前段局部区间、上下文区间、实际采样区间。采样帧数按本机 H3 的 17k+5 网格向上对齐，必须容纳上下文与新增内容；保护上下文不再次输出，末端对齐余量可以不进入成片。精确裁切属于本档位的明确输出合同，不改变对白、动作的剧情预算。

规划器先按硬件选物理子段，再把台词/动作落点映射进去。不能为了固定 61 秒裁断一句话。若某个不可分割动作或完整台词放不进硬件允许的子段，生成前报出段号与冲突，不静默删词、变速或补空白。

冻结尾部检测可能减少可用帧数：若不足目标，保留已完成段，从有效上下文补生成剩余内容；不足时不标记成片完成。视频以解码帧数验收，音轨以时间戳与解码样本数验收，允许编码容器固有的少量音频 padding，但不能用音频 padding 代替视频时长。

## 执行与连续性

第一版以 FL2VA/Base 的 T2VA 或真实首帧 I2VA 为范围；后续使用原始 AV latent 续拍。优先通过独立适配器调用 H3 Infinite 的 native masked AV 能力，记录安装版本与所需核心能力。未经验证的环境不可静默降级为 RGB 尾帧拼接。

普通身份图不会自动变成首帧。REF2VA、多参考音色和 Fish 锁音路径不能套用 FL2VA 续拍假装等价；第一版应明确提示长片续拍暂不支持这些组合，普通单段档位照常可用。无需用户必须上传素材；T2VA 可从文字开片，已有首帧则走 I2VA。

每段按「条件构造→采样→保存原始 AV latent/净输出区间→解码→可选精修→编码」运行。上一段只保留必要的上下文和文件索引，成片合并从磁盘读取，不把 61 秒 2K RGB 全部堆入内存。GPU 上不同时运行两个生成任务。

续接边界分别处理画面与声音：有效视频尾部避开冻结，保护仍在结束的音频尾部；重叠部分不二次计时。默认不叠加接缝重新采样或自动换种子重摇，避免隐性增加耗时；生成结果不合格时保留失败记录供重做。

## 显存与清晰度

- 24/32GB：先验证七段故事节拍可映射成安全采样段；1080p 复用 H3 二采→3B 精修，2K 按逐段实测显存决定是否可开放。
- 8/12/16GB：使用更短的物理子段和较小的原生画布，故事时间轴仍为 61 秒。上下文也占预算。只有真实 8GB 设备跑通后才能标记“8GB 已验证”，本机 32GB 的限额模拟不是同等证据。
- 首版未通过的档位应显示实验/不可用与原因，不将“可以生成低清片段”写成“8GB 流畅 2K 长片”。
- 精修默认逐段执行，便于及时卸载和断点恢复；连续生成的基准仍使用未经精修的原始 AV latent。
- 时长增长必然增加总运算量。验收比较每输出秒耗时与采样/精修/编码分项，不能与单条 5 秒任务比较总秒数后宣称加速。

## 提示词编译

全片设定只在界面填写一次，执行时为每个段重新注入必要身份/场景/声线约束；模型不会自动读取 UI 的项目备注。每段只提交当前动作，不把整份 61 秒故事反复送入每一次采样。

用户填写净新增内容的局部时间；编译器为有前置保护上下文的采样段平移其内部时间戳，并注明保护区延续既有动作。切段不会把第 27 秒的事件重新标成“第 27 秒发生于一个 9 秒样本”。

Base 执行稿遵循官方 integrated_multimodal_description、overall_soundscape、non_diegetic_music 三字段；只有真实输入对应的 Picture 标签才能出现。中文对白逐字保留，其余执行叙述按英文模板渲染。自定义开场/结束状态等字段留在导演规划层。

无音色样本时使用稳定声线文字描述，但不承诺声纹锁定。先交付无对白连续动作示例，对白版必须检查句界和声音身份；配乐默认关闭或在合成阶段使用一条用户提供的连续音乐，避免七段分别起奏。

## 断点与取消

每个项目在 output/h3_longfilm/<id>/ 下保存 manifest、分段视频、原始 latent、参数与提示词指纹、模型身份、真实帧区间和耗时。清单原子更新；中断后只复用校验通过的文件。修改第 N 段提示词会使 N 及其后依赖段失效；仅修改最终超分不重做采样。停止后续不删除已完成文件，不中断其他用户任务。

## 验收

1. 普通档位的 4–15 秒、音色、横竖屏和输出回退测试继续通过。
2. 总预算严格为 1464 帧；物理子段、上下文和对齐余量均有台账；拼接无重叠重复帧。
3. 模拟节点测试覆盖段间传递、资源释放、取消、崩溃恢复、改词失效、缺依赖和音频边界。
4. 本机真实短链先跑两段，检查人物、道具、运动和声音；再跑完整 61 秒并测量各阶段耗时/峰值显存。
5. 1080p 与 2K 分别验收，8GB 单独记录设备与成功条件。无 GPU 完整运行不得宣称画质、性能或完整功能已验证。
6. 交付独立 U11 长片工作流、示例规划稿、使用说明、备份与同步记录。
