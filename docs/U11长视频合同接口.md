# U11 长视频合同接口

此接口是原 U11 续拍引擎的内部协议及高级兼容接口。普通用户直接在原导演台填写超过 15 秒的总时长、整片提示词及原有素材；后台从提示词派生该协议，不需要手工导入 JSON。完整使用与验证范围见 [U11 原生 AV 长视频](U11原生AV长视频.md)。

原导演台的 `duration` 是整片秒数，自动路由阈值为 15 秒。`scene_contract` 只作为后台派生数据和已有专家配置的兼容入口。总时长按 24 FPS 转帧；30、60、90 秒分别为 720、1440、2160 帧。普通用户不填写物理窗长度、latent 索引或手工拼片。

## 机器输入

`scene_contract` 是一个 JSON 对象或该对象的 JSON 文本。当前格式为 `schema_version: 1`、`fps: 24`。`total_frames` 可省略，提供时必须与入口目标时长一致。

必需字符串：`subject_definitions`、`summary`、`retention_analysis`、`scale_contract`、`overall_soundscape`、`non_diegetic_music`。其中 `scale_contract` 必须包含数值尺寸。输入没有独立必需的 `detailed_description`：执行器从完整动作节拍和对白生成它。

`beats` 是非空数组。每项含唯一 `id`、全局半开帧区间 `start_frame/end_frame`、`action`，可有 `camera`、`sound` 和布尔 `indivisible`。动作可以重叠，区间并集必须覆盖整片。`indivisible: true` 的动作不得被交接切开。

`dialogues` 是完整发声事件数组，可为空。每项含唯一 `id`、全局半开帧区间、`speaker` 和逐字 `text`；可有 `language` 和 `audio_slot: 1..3`。`speaker` 同时保留稳定 `<Subject N>` 与 `(Sx)`，`audio_slot` 表示原导演台实际音频槽。不要把音频槽号直接当人物或声源编号，也不要因换物理窗重新分配已由 AV 历史建立的身份。`text` 不含外层 `<d>`，执行器负责添加且不会改写其中的时钟或引用字面量。整句只能归属一个新增窗口。

`reference_assets`、`scale_reference`、版本、审查状态等原始元数据可以随合同保留。路径、哈希、计划槽位与 `approved/mounted` 声明不能代替真实挂载及实际审查。执行器另外冻结原 U11 真正连接的素材、模型、LoRA 和父 clean AV。

## 相位、参考与音色

以下字段是可选扩展，旧合同不加时保留继承行为：

```json
{
  "voice_policy": "dialogue_only",
  "reference_selection": {"pictures": [1, 3], "audios": [1]},
  "window_overrides": [
    {
      "new_start": 294,
      "new_end": 549,
      "remaining_beats": [
        {"id": "continue", "action": "Continue the current empty-hand conversation."}
      ],
      "sections": {"summary": "Continue the conversation in the present scene."},
      "reference_selection": {"pictures": [1, 3], "audios": []},
      "forward_frames": 0
    }
  ]
}
```

该片段仅展示字段；`continue` 必须真实存在于 `beats`，窗口范围必须来自本合同的实际规划，图片/音频编号必须真实存在。它不是独立可运行的故事或已审素材声明。

- `window_overrides` 必须精确匹配规划所得 `new_start/new_end`，不得重复或重叠。先调用 `validate_window_overrides(contract, windows)` 检查全部窗口，避免生成到后段才发现旧计划不匹配。
- `remaining_beats` 按既有 beat `id` 替换该窗当前相位的整组 `action/camera/sound`。未填写的旧机位与声音不继承。使用此扩展时，原全局摘要只留审计；没有显式本窗摘要时使用中性的当前阶段摘要。
- `sections` 只允许六个官方段落名：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。其中 `detailed_description` 是当前相位补充，不能粘贴已包含完整对白的预编译整窗正文，否则会重复下达事件。身份、尺度、动作、对白及已完成状态应分别保留其职责。
- `reference_selection` 中的编号指**原导演台实际扁平顺序**：存在的首图、尾图、普通参考图依次编号；音频按实际原槽位编号。有序选择会同步压缩连接和导演用 Picture/Audio 引用，Subject/Sx 与逐字台词不重排。未知或缺失编号、悬空引用及无法安全移除的混合身份描述会报错。换槽还会检查实际 Director 的裁切/过滤策略；选择被自动移除的动作板，或换槽会改变裁切行为时，要求使用已审独立参考图或兼容的原职责。
- `voice_policy` 默认 `inherit`。显式 `dialogue_only` 在本窗没有新对白时移除本地音色参考，继承实际历史中的人物声音身份。显式 `audios: []` 也省去本地参考音频；不会自动声称某种替代声线与原声等价。
- `target_audio` 是可选的高级完整音轨合同，可在全片或精确匹配的 `window_overrides` 指定 `kind: complete_wav` 或 `kind: fish`；缺省保持原联合 AV 路径。它不是新增 Audio 槽位。WAV、全句来源、完整声场、采样时钟、原音色绑定和锁音频返修要求见 [完整目标音轨](U11原生AV长视频.md#完整目标音轨代码接入待-gpu-验收)；运行时会进一步核验实际文件和物理窗，不能用 schema 通过替代媒体验收。
- `parent_reference` 可在全片或精确匹配的覆盖中指定实际父帧软参考。`{"mode":"replace","picture_id":2,"frame_policy":"delivery_last"}` 替换当窗确已选中的原 ID2，保留编号与数量，适用于既有十一 ID 内部素材库；`forward_last` 另需精确前向审查。普通原导演台长片内部使用 append，静态最多八张加一张自动父帧，不增加上传控件。显式 `reference_selection` 不能混用 append；缺省高级合同保留原行为。真实来源冻结、缓存和恢复规则见 [实际父帧软参考](U11原生AV长视频.md#实际父帧软参考)。
- `forward_frames` 默认 0。入口已接入真实已审来源尾段、双流映射和指纹保护；正数必须符合原生相位且真实来源有足够余量。面板会暂停并要求审查实际来源秒段、填写实际自由起点状态，之后才增强和续拍。填入数值本身不产生 AV 条件或审批；任意未来音频锚点等未实现协议仍明确拒绝。

## 时钟与结构化动作

所有区间都是 24 FPS 全局帧。可用 `timed_actions` 把一个 beat 分成明确阶段，每项含 `start_frame/end_frame/action`，可有 `camera/sound`。跨窗动作被裁到中途时，用明确余相表达，避免让模型重新执行整个拿、喝、放动作链。

推荐帧时钟 `{{frame:1569}}`。编译器将其变为当前窗局部秒数；明确的 `at 65.400.`、`by 73.400.`、带单位的中英文事件时钟与范围也会转换。人数、尺寸、距离范围和“保持 3 秒”等相对时长保留原意。逐字 `<d>` 内容永不做这种替换。

技能内部 `{{clock:event_id}}` 必须在导出时依据 `timed_events` 解析为 `{{frame:N}}`。不能把已变成局部秒数的文本再当全局文本交给 U11 二次转换。

## 技能导出边界

H3 技能的 `source_beats`、导演单元、资产清单、`physical_windows` 和 `compiled-plan.json` 是较丰富的规划视图；它们不能原样冒充上述 `scene_contract`。导出器应从同一事实源派生 `beats/dialogues/window_overrides`，不另写第二套剧情。

导出时必须：保留全局完整对白与稳定身份；使用实际 U11 规划边界；把当前相位写成替换项；把技能引用映射到原 U11 真实绑定编号；保留未审、未挂载和未观测状态；不把预期末态写成已观测父状态。续窗执行只读取实际接受父窗的 `observed_outgoing_state`。新接口的离线互通测试不授予 GPU、资产或成片质量通过。

规范由 `nodes/long_video_plan.py` 的 `validate_contract/validate_window_overrides` 与生产适配器 `nodes/long_video_graph.py` 的 `apply_window_reference_policy` 共同执行。后者在不可变请求与指纹创建前校验实际绑定和 Director 预处理策略。纯 `long_video_references.apply_reference_policy` 供静态数据编译，追踪标记为 `not_performed_static`；生产适配器的显式选择标记为 `director_policy_checked`，静态快照不能代替它。

机器可读 schema 为 [u11_long_video_contract.schema.json](../templates/u11_long_video_contract.schema.json)，仓库内的入口示例为 [英文](../examples/u11_long_video_scene_contract.en.json)与[中文](../examples/u11_long_video_scene_contract.zh.json)。它们已与真实技能导出视图逐字节核对。跨字段覆盖、对白所有权、窗口边界与真实挂载仍需要运行时校验，JSON Schema 不能独自证明这些事实。

普通返修使用成片 `start_seconds/end_seconds`，不填写 latent 索引。服务器先核对当前 take、受保护 AV 与实际范围，再返回向外对齐的 `conditioning_extent.video_seconds/audio_seconds`。浮点序列化产生的单个 ULP 误差可对齐到本来的整数帧；真实越界和受保护区域重叠仍拒绝。默认视频返修锁住音频；专家 API 另支持音频、联合 AV、时域软权重和下述已审原生视频参考。空间 mask、任意路径与未来音频锚点协议不支持。显式整窗重生成会变更本窗种子，自动恢复保留原种子与返修配方。

专家返修可先调用 `review_video_reference`，提供 `source_take`、`source_steps`、实际观看范围 `scope` 与姿态/道具状态 `observed_state`，取得 `video_reference_review` 文件描述符。随后在原 `repair` 请求中附加 `video_reference: {source_take, source_steps, target_steps, review}`；`review` 为该描述符。来源必须是同项目当前接受的较早窗口，且仅可使用尚未交付、也未被已接受子窗前向消费的原生尾部。两个范围必须等长、对齐原生五步组，目标完全位于本次正权重视频返修区，且留有自由视频用于采样。

参考视频在采样前写入视频 latent 并受原有 noise mask 保护，不改变完整音频。提交、创建 take 和运行时均复核原生预览、clean AV、来源接受记录与独立参考审查回执；来源被换掉、撤回或文件改变会拒绝。此能力不新增普通页面选项，也不自动批准动作质量。真实边界、人物、道具与声音仍须检查；原生参考的本次办公室 GPU 验证尚未完成。
