# 原导演台的文武双全作者配方

在原 U11 导演台选择 **REF2VA → 质量优先二采样 → 二采高级设置 → 动作增强：文武双全（作者配方）**。二采方法会自动采用对应的 SelfLift；不需要另导入工作流，也不需要在附加 LoRA 中再选这些模型。默认动作增强仍为关闭。

可使用无音色、H3 原生音色参考或完整复用音频。Fish 克隆分支不适用。单段仍是物理 4–15 秒；要做更长视频，继续在原导演台填写总时长和完整时间线，使用既有长视频入口及其音画审核流程。图像、音频槽位和主体绑定数量保持原有上限。长片的原生声音模式限制仍然有效；不能因为短片支持完整复用音频，就推定长片也支持该方式。

SelfLift 启动需要至少 **20GB 总显存、18GB 空闲显存**，并需要支持全局路径的 SelfLift-Avatar 和实际可用的原生 Sol-Attn。这只是启动条件，不保证任何尺寸、时长都不会 OOM。8GB 请继续使用原低显存路线。切换到不兼容配置时，作者选项会保留并显示原因，可以直接把动作增强设为关闭；不会假装执行了另一套作者配方。

固定使用 24FPS，不启用 RIFE。

## 配方来源和执行内容

来源是用户指定的 [YZ_金鱼发布视频](https://www.bilibili.com/video/BV1LKJm6VELc/)、[作者工作流页面](https://www.runninghub.cn/post/2109907990638850050)和先前提供的归档 JSON，详细证据见[来源比较记录](research/2026-11-13-wenwu-workflow-comparison.md)。归档图的四个动作节点原本处于 bypass；本项目只有主动选该配置时才开启整套动作链，不把它们强加给日常生成。

| 项目 | 作者配方 |
| --- | --- |
| 调度和采样 | simple / Euler，12 步，6+6 渐进二采 |
| Sigma shift | 视频 12，音频 3 |
| CFG / 低分辨率比例 | 1 / 0.6 |
| 第一项 LoRA | DMAD v4 FRO，0.8 |
| 第二项 LoRA | Mystic V1，0.35 |
| 第三项 LoRA | Combat V2，0.65 |
| 第四项 LoRA | Motion Repair V2，0.35 |
| 第五项 LoRA | Fight Flow V1，0.35 |
| 第六项 LoRA | speed slider 1.1，3.0 |
| Latent 放大 | LMS v0.1 |

保留了本项目已采用的 Avatar 全局高分辨率执行、原生注意力及长片双流保护；归档作者图使用的是旧版 full-frame 路线，因此这是**按作者参数集成的现代执行适配**，不能称为逐像素复刻。归档速度节点的中文文件名与作者当前公开页面的英文 `H3_speed_slider_1.1.safetensors` 尚未证明是相同字节；本项目采用后者，并记录这个差异。

缺少任何必需权重都会明确报错，实际应用 LoRA 失败也会停止；不会用旧 Motion Repair、Mystic V5、Turbo 或其他放大模型补位后继续声称使用了作者完整配方。附加 LoRA 中如已选了这些适配器或 Mystic V5，请关闭冲突项；普通路线的附加 LoRA 行为不变。执行报告记录配方和实际加载项，长片也冻结这些资源的文件身份。

完整文件名、固定版本下载地址及 SHA-256 见[权重来源记录](research/2026-11-13-wenwu-author-assets.md)。Mystic V1 的文件身份以原作者 Civitai API 为依据；所列 HF 镜像是第三方镜像，大小和 SHA-256 与该原始记录一致。模型文件不随代码提交。

## 提示词和效果判断

继续使用原 H3 提示词、参考图和音色绑定方式。文戏应写可见的表情、重心变化、听者反应和对白节奏；武戏应先写动作所有者、路径、接触/闪避、受力结果和恢复，再写对白。Combat 作者建议先采用无触发词方式，不需要为了启用本配方把触发词塞进所有日常镜头。[来源：Combat V2 发布说明](https://api.bilibili.com/x/web-interface/view?bvid=BV1rTbf6CEtj)

这套参数尚不能视为本机 GPU 画质验收通过。它从原 SelfLift 的 beta 10 步变为 simple 12 步，高分辨率段从 4 步变成 6 步；仅凭名称不能承诺更快，也不能承诺必定去除油腻、塑料感或复杂武戏瑕疵。要比较效果，应固定输入、声音、seed、尺寸和时长，检查肤色、发丝、运动、接缝和真实耗时。
