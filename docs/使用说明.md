# MiniMax H3 导演台 Plus 使用说明

## 先看本机状态

先运行工作流里的“本机能力状态”节点，或访问 `/h3-director-plus/status`。状态会分别列出 H3 FL2VA/REF2VA 基础模型、FL/Reference 训练型二采所需的精确 LoRA、3D latent 放大节点与模型、`H3SigmaRefiner`、Sage/EasyCache、RIFE 和 RTX VSR。Fish S2 必须同时满足节点和 `models/fishaudioS2/` 模型目录；只有节点、没有模型时会明确显示“模型未就绪”。RTX VSR 会在 `postprocess.rtx_vsr` 中单独显示依赖状态。插件不会静默下载模型。

## 模式选择

- **T2VA**：默认是纯文本生成视频，不需要图片；如果启用音色参考，会自动切换到 REF2VA 音频参考路线。
- **I2VA**：切换到 I2VA 后，在导演台内直接上传首帧图片。没有音色时使用 `fl2va_model`，首帧是硬约束；启用音色后自动改走 `ref2va_model`。
- **FL2VA**：切换到 FL2VA 后，在导演台内直接上传首帧和尾帧。没有音色时两张图是硬首尾帧；启用音色后两张图变成提示词级端点 reference。
- **L2VA**：切换到 L2VA 后，在导演台内直接上传尾帧图片，保持原生 H3 尾帧语义。
- **REF2VA**：切换后直接显示 9 个参考图槽。图 1/图 2 标注为“起始构图建议/结束构图建议”，其余为角色、场景、服装、道具或风格参考。编号与 `<Picture N>` 一一对应，必须从图 1 开始连续上传，不能跳号。只上传两张图时，可以在提示词中说明“从 `<Picture 1>` 的构图开始，最终落到 `<Picture 2>` 的构图”，但它们仍属于 reference 提示词约束，不是 FL2VA 硬端点。

## 音色参考

选择“**H3 原生音色参考**”，切换到支持音色的模式后，最多可上传 3 路参考音频。每一路先填写“对应角色”，再上传样本；提示词用 `<Audio 1>`、`<Audio 2>`、`<Audio 3>` 指定人物。音色也必须从 1 开始连续上传，不能跳号。示例：`角色甲使用 <Audio 1> 的音色说：“我们回家。”`。这条路线只提取音色、说话方式和表达特征，不复用上传音频的完整内容，也不会把原音频当作视频声音直接拼接。

T2VA、I2VA、FL2VA 和 L2VA 都支持这个音色入口。控制器会把图片改写为 H3 reference 提示词，并显示实际后端 `ref2va_model`。提示词应直接写出角色、动作、镜头、对白和时间点；音色样本对应文本可填在“参考音频文本”。

切换模式后，隐藏上传槽中的旧图片不会继续生效：T2VA 会清除首帧、尾帧和参考图，I2VA 只保留首帧，L2VA 只保留尾帧，FL2VA 只保留首尾帧。导演指南和日志会显示被忽略的残留素材。

“**Fish S2 高级音色锁定**”默认关闭。它先用 Fish S2 根据目标对白生成新对白音频，再把新音频送回 H3 reference。只有 Fish 模型就绪、确实需要改变对白内容时才打开；没有模型时请保持关闭。

## 性能预设

### 免费智能 1080p（默认）

“免费智能 1080p”是导演台和 API 模板的默认预设：本地免费执行，不调用付费云服务。普通显存优先保持 20 步采样并启用 SageAttention 加速，随后用 `RealESRGAN_x2plus.pth` 单次 X2 重建到至少 1080p；低显存才切换到受限路线。生成阶段分辨率不等于最终输出分辨率：H3 先以显存安全的原生尺寸采样，再由后处理得到最终 MP4 尺寸。低显存二采最多 6 秒；启动前会检查空闲显存，无法满足时会在排队前给出原因。

REF2VA 和 Fish 必须使用安全的 reference 路线（`quality_sage`、`low_vram` 或 `ref_fast_4step`），REF2VA 不使用训练型 reference latent 二采。旧工作流中保存的 `trained_latent_ref` 只作为兼容标识，加载时会提示迁移，不会实际调用该路线。

- **T2VA / I2VA / FL2VA / L2VA（无音色）**：只显示“免费智能 1080p”和“稳定质量”。前者普通显存使用 20 步 SageAttention + 免费 X2 超分，低显存自动切换受限路线；后者保持原生质量路线。
- **REF2VA 或 H3 原生音色参考**：只显示“免费智能 1080p”和“参考高清（原生20步）”。参考高清是原生 20 步 + SageAttention，不使用 Turbo/二采；Fish S2 继续使用兼容的 reference 流程。
- **T2VA / I2VA / FL2VA / L2VA + H3 原生音色参考**：自动走 H3 reference 后端，显示上述两项 REF2VA 兼容预设；首尾图片改为提示词级参考，不再套用 FL2VA 硬端点语义。
- **旧工作流兼容**：其他历史预设仍可由 API 和已保存节点加载，但不再出现在导演台的普通预设下拉框中。
- **质量优先加速**：保持原生 20 步，只启用 SageAttention，并使用 ComfyUI 动态分层加载；关闭 Turbo LoRA 与 EasyCache。它比 4 步慢，但画质最接近稳定质量，不需要额外下载模型；Sage 不可用时会保持原生 20 步，不会偷偷降到低步数。
- **质量优先二采样**：FL 后端使用 `trained_latent_fl` 的匹配 LoRA 和 3D latent 放大；REF2VA 不使用训练型 reference latent 二采，改走 `quality_sage`、`low_vram` 或 `ref_fast_4step`。旧状态 `trained_latent_ref` 与 `H3SigmaRefiner` 仅保留为迁移/依赖识别信息，不会实际执行。首采得到的 H3 AV latent 会分离音频与视频，音频原样保留；最终放大器只处理视频通道。最终 RTX 路线只执行一次 `HIGHBITRATE_ULTRA` VSR，`DEBLUR_LOW` 已停用；训练型二采固定关闭 RIFE、Sage 和 EasyCache，避免灰屏、颗粒、重影或跳帧。
- **低显存**：8 步 + H3 内存高效 Sage，关闭 EasyCache，使用 ComfyUI 动态分层加载。插件会按时长自动降低 H3 原生采样尺寸；最终输出路线决定是否放大到目标尺寸。4/6/8/10/12/15 秒的原生上限约为 1.00/0.65/0.50/0.36/0.30/0.26 MP。8–12GB 显存不执行训练型高分辨率二采，低显存不开放 4K，最终目标上限为 1080p。
- **低显存二采**：给 RTX 3070 8GB 级显卡单独开放的受限真二采，不是把高显存档强行解除拦截。1080p 支持 4–6 秒：4 秒保留约 0.46MP 首采和约 1.03MP 神经二采；5/6 秒按时长降低首采网格（约 0.37/0.31MP），用空间细节换时长，再由 `RealESRGAN_x2plus.pth` 逐帧重建到 FHD。最终目标超过 FHD 像素预算时自动回到“1080p FHD”。最终路线固定为单独的 `AI 自动超分`，不会再执行 RTX VSR，也不会把两个放大器叠加。整个采样阶段启用 ComfyUI LOW_VRAM，阶段间卸载 H3/放大模型，最终使用 CRF 16 并关闭 RIFE。启动前总显存须达到 8GB 级且至少有 6.0GB CUDA 空闲显存；缺少 X2 模型会在 H3 开始前提示。它比普通低显存明显更慢，且 1080p 是 AI 重建尺寸，不是 H3 原生 1080p 采样；7 秒以上仍会在采样前拒绝。
- **自定义**：仅为旧工作流和 API 保留，不在导演台普通预设下拉框显示。

### 官方 LightX2V LoRA 校验

极速 4 步及其他依赖官方 LightX2V LoRA 的性能档位，现由 ComfyUI 核心 `LoraLoaderModelOnly` 内置加载器应用。开始采样前会核对实际新增的模型补丁数；成功日志会包含 `patch_delta=<正整数>`。如果核心加载器抛错（例如文件损坏或格式不支持），或完全没有新增补丁，会在首个 H3 采样节点前停止；常见的缺文件、损坏文件和零补丁错误会包含解析后的 LoRA 文件名，不会把基础模型按 4/8 步继续生成。

### 训练型二采所需节点和模型

选择“质量优先二采样”或“低显存二采”前必须安装以下资产；导演台会在 H3 开始采样前检查，缺少任何一项都会直接给出中文文件名，不会跑到最后才报错：

- 训练型 3D latent 放大节点：[LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler)。必须使用包含长视频时间分块、重叠融合、宽高独立 32 对齐和执行后卸载模型的新版本。
- 放大模型 `minimax_h3_latent_upscaler_3d_bf16.safetensors`，放到 `ComfyUI/models/latent_upscale_models/`。
- FL 路线 LoRA：`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` 与 `minimax_h3_fl2v_turbo_4step_v1.1_768p_comfyui_bf16.safetensors`，放到 `ComfyUI/models/loras/`。
- Reference 路线 LoRA：`minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors`，放到 `ComfyUI/models/loras/`；同时安装 [ComfyUI-YCNodes-MiniMax-H3](https://github.com/yichengup/ComfyUI-YCNodes-MiniMax-H3)，提供 `H3SigmaRefiner`。

## 最终输出与 AI 重建

在“生成规格”中选择唯一的“最终输出”路线，分辨率档位是最终保存视频的目标尺寸，不需要连接第二个放大节点：

- **原生尺寸直出**：保存 H3 实际生成尺寸；即使选择 2K/4K，也不会放大。
- **Lanczos 快速放大**：CPU 分块重采样，兼容性最好、显存占用低，但不会凭空重建细节。
- **AI 自动超分**：使用 `ComfyUI/models/upscale_models/` 中的通用模型逐帧重建细节。默认“自动选择”，会按目标倍率优先选择 X2/X4 模型；也可以在展开的“AI 超分模型”下拉框中指定已安装模型。模型缺失会在 H3 生成前报错。
- **AI 细节重建（RTX VSR）**：使用 NVIDIA RTX VSR；首次使用前需要安装其依赖和匹配驱动，节点会在生成前检查。普通性能预设使用 HIGH/ULTRA；质量优先二采样在 2K/4K 路线固定使用 `HIGHBITRATE_ULTRA`；低显存二采固定使用 `ULTRA`，兼顾 8GB 显存和最终细节。目标与原生尺寸相同会自动旁路，目标更小会使用高质量缩小。

四条路线都只保存一个最终 MP4，不会同时输出原始视频和放大视频。放大只在解码后的帧上处理，不重新生成镜头时间线或对白内容。

两个训练型二采预设的最终 H.264 都使用 CRF 16；若输出节点原本设为 0–15，则保留更高质量值。编码完成后会以 stream-copy 无损写入 BT.709 limited-range 标记，视频帧和音频都不会再次编码；即使标记步骤失败，也会保留已经成功生成的 MP4 并在日志中明确提示。其他性能预设继续使用各自原有编码值。

导演台显示的三个尺寸含义不同：`H3首采` 是扩散模型第一阶段的实际画布；`神经latent二采` 是训练型放大并低 sigma 重绘后的真实细节基准；`最终输出` 才是 MP4 的像素尺寸。高显存档位的 2K 16:9 通常为约 `1280×704 -> 1920×1056 -> 2560×1440`，最后 RTX VSR 只做约 1.33–1.36 倍重建，不再从约 0.2 MP 硬拉到 2K；`1920×1056不是原生2K`，而是神经二采后的细节基准。4K 为 `约1080p神经二采基准 -> 3840×2160逐帧RTX VSR`；4K 不是 H3 原生采样。最终文件仍须用媒体属性或 `ffprobe` 验证为 2560×1440 / 3840×2160，像素尺寸达到 2K/4K 不等于源细节天然就是原生 2K/4K。

训练型二采和单次 RTX 后处理会增加额外时间，但不提高 H3 显存峰值；输入输出会先做等比中心裁切，随机种子仍影响生成纹理。

28GB 及以上显存且启动前至少有 24GB 空闲显存时，选择“质量优先二采样 + 1080p FHD”会自动启用 **1080p 平衡二采**：横向为 `1344×768 -> 2016×1152 -> 1920×1080`，竖向为对应旋转尺寸。最后先等比中心裁切约 1.6% 的边缘，再用分块 Lanczos 缩小，不执行 RTX VSR，也不需要 NVIDIA VFX 依赖。与保守 FHD 网格相比，神经二采像素增加约 14%，但仍保留 FL 4+4 / Reference 4+5 步、原视频时长和原音频。

20–24GB 级显卡，或 28GB+ 显卡因刚取消任务只剩 18–24GB 空闲显存时，会自动切换为 **1080p 保守 FHD 二采**：横向为 `1280×704 -> 1920×1056 -> 1920×1080`，竖向为对应旋转尺寸。它至少需要 18GB 空闲显存，最终只做轻量中心裁切与 Lanczos 对齐，同样不执行 RTX VSR。这个放宽只适用于精确 1080p FHD；2K/4K 仍使用原来的高显存门槛，不会套用 FHD 预算。日志与导演台 warning 会明确显示实际命中的链路。

### 上传素材的移除

已上传图片或音频会显示“更换”和“移除”。移除只清空节点的隐藏 widget、刷新预览并标记画布为 dirty，不调用删除 API，因此“移除只取消节点引用，不删除原文件”。REF2VA 删除中间图片后，后续槽位会向前补位，并提示检查 `<Picture N>`；音色音频会和 `voice_reference_name_1..3` 一起补位，并提示检查 `<Audio N>` 与角色名。I2VA/FL2VA/L2VA 的首帧和尾帧是独立槽位，清空其中一个不会改变另一个。

### 运动平滑

- **关闭（默认，24 FPS）**：保留 H3 原始帧，不执行插帧，避免无需要时增加合成帧柔化和处理时间。
- **RIFE 2x（48 FPS）**：按相邻帧逐对生成中间帧，N 帧输出为 `2N-1` 帧。编码帧率同步翻倍，所以视频时长、对白时间和音频内容都不变；检测到真正硬切时会旁路插值，避免合成跨镜头鬼影。

RIFE 不是整段批量节点：它逐对推理并把帧流直接交给 RTX VSR，提前停止或编码失败时也会释放上游 RIFE 与下游 VSR 模型。启用前请从 [Comfy-Org 官方模型库](https://huggingface.co/Comfy-Org/frame_interpolation/resolve/main/frame_interpolation/rife_v4.26.safetensors) 下载 `rife_v4.26.safetensors`，放到 `ComfyUI/models/frame_interpolation/`；缺少模型会在 H3 采样前提示安装，不会等视频生成结束才报错。两个训练型二采预设都不开放 RIFE，以避免重影和额外显存峰值；普通低显存模式也不开放 RIFE。

### 最终音频

- **自动增强响度（默认）**：最终编码前提升过小的 H3 音轨，峰值目标为 -1.5 dBFS，最多提升 30 dB；静音保持静音，源 AUDIO 不会被原地修改。
- **保持原始响度**：不处理 H3 解码音频，适合后续在剪辑软件中自行混音。

使用 RTX VSR 前，必须在当前 ComfyUI Python 中安装官方 `nvidia-vfx` wheel；以下 DaSiWa requirements 安装命令可保留为依赖安装入口：

```powershell
D:\ComfyUI_windows_portable-G313\python_embeded\python.exe -m pip install -r D:\ComfyUI_windows_portable-G313\ComfyUI\custom_nodes\ComfyUI-DaSiWa-Nodes\requirements.txt
```

Linux 请使用 NVIDIA VSR 支持驱动分支 `570.190+`、`580.82+` 或 `590.44+`，不要求安装 Windows NVIDIA Broadcast SDK。Windows 请检查 NVIDIA 驱动、官方 `nvidia-vfx` wheel 与 NVIDIA Broadcast SDK/Video Effects 运行库兼容。导演台会在 H3 开始前，以真实 `640×360 → 1280×720` 单帧执行一次 RTX VSR `load + run`；失败会提前停止，不会在视频生成后才报错。

切换模式或音色模式后，导演台会自动刷新可用预设。旧工作流如果保存了不适用的组合，会自动回退到“稳定质量”，并在警告输出中说明原因。

U11 的“运动平滑”使用流式 RIFE 路径，不调用会构造整段双倍帧批次的旧插帧链。训练型二采已内置到 `H3 训练型 3D Latent 二采（自动旁路）` 节点，用户只需选择性能预设，不需要手动连接分支；其他预设自动执行单采样路线。二采节点不再保留 VideoVAE 输入，也不会执行整段 VAE 解码、图像放大、再编码的高内存往返。

## 分辨率与排版

导演台的“生成规格”是唯一生效的视频时长、画面比例和最终输出目标分辨率入口。左侧 Settings 中原有的 `resolution_preset`、`aspect_preset_when_not_image` 和 `swap_aspect_when_not_image` 已移除，避免两边设置不一致。H3 原生时长支持 4-15 秒整数。比例包含横向 `3:2`、`4:3`、`8:5`、`16:9`、`21:9`，对应竖向比例、`1:1` 和 `CUSTOM`；普通档位宽高按 32 对齐，`1080p FHD`、`2K QHD` 和 `4K UHD` 在 16:9 下保持精确的 1920×1080、2560×1440、3840×2160（9:16 自动交换）。

这里的目标尺寸不是另一套需要手动配置的生成参数。低显存模式下，工作流自动执行 `H3 低分辨率采样 -> VAE 解码 -> 曝光保护 -> 选中的单一后处理 -> MP4 保存`；用户不需要连接节点。8–12GB 低显存档位最高开放 1080p，不允许以极低源分辨率硬拉 4K。其他档位的放大路线都按帧或小块处理，避免在显存中保留整段 2K/4K 视频；通用 AI 和 RTX VSR 只增强可恢复的边缘与纹理，不改变镜头时间线或重新生成内容。

“噪音种子”旁边可选择“固定、每次递增、每次递减、每次随机”。这是 ComfyUI 原生的生成后控制：当前任务使用当前显示的 seed，任务提交后再按所选模式准备下一次 seed。固定适合复现画面；递增/递减适合连续比较；随机适合批量探索。

U11 将主导演台、素材/路由、预览输出分为固定区域，上传槽保持两列规整排列，不需要手动连接图片或音频节点。导演台现有的快速设置、生成规格、导演与素材、音色参考、实际后端分区是稳定界面基线，后续功能优先在对应分区内扩展，不随意改变整体排列。
