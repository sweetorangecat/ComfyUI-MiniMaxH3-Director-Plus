# MiniMax H3 导演台 Plus 使用说明

## 先看本机状态

先运行工作流里的“本机能力状态”节点，或访问 `/h3-director-plus/status`。当前安装通常可以看到 H3 FL2VA、REF2VA、GGUF、LightX2V LoRA、Sage、EasyCache、SolAttn、RIFE 和 RTX/LTX 后处理。Fish S2 必须同时满足节点和 `models/fishaudioS2/` 模型目录；只有节点、没有模型时会明确显示“模型未就绪”。RTX VSR 会在 `postprocess.rtx_vsr` 中单独显示依赖状态。插件不会静默下载模型。

## 模式选择

- **T2VA**：纯文本生成视频，不需要图片或音色。
- **I2VA**：切换到 I2VA 后，在导演台内直接上传首帧图片。没有音色时使用 `fl2va_model`，首帧是硬约束；启用音色后自动改走 `ref2va_model`。
- **FL2VA**：切换到 FL2VA 后，在导演台内直接上传首帧和尾帧。没有音色时两张图是硬首尾帧；启用音色后两张图变成提示词级端点 reference。
- **L2VA**：切换到 L2VA 后，在导演台内直接上传尾帧图片，保持原生 H3 尾帧语义。
- **REF2VA**：切换后直接显示 9 个参考图槽。图 1/图 2 标注为“起始构图建议/结束构图建议”，其余为角色、场景、服装、道具或风格参考。编号与 `<Picture N>` 一一对应，必须从图 1 开始连续上传，不能跳号。只上传两张图时，可以在提示词中说明“从 `<Picture 1>` 的构图开始，最终落到 `<Picture 2>` 的构图”，但它们仍属于 reference 提示词约束，不是 FL2VA 硬端点。

## 音色参考

选择“**H3 原生音色参考**”，切换到支持音色的模式后，最多可上传 3 路参考音频。每一路先填写“对应角色”，再上传样本；提示词用 `<Audio 1>`、`<Audio 2>`、`<Audio 3>` 指定人物。音色也必须从 1 开始连续上传，不能跳号。示例：`角色甲使用 <Audio 1> 的音色说：“我们回家。”`。这条路线只提取音色、说话方式和表达特征，不复用上传音频的完整内容，也不会把原音频当作视频声音直接拼接。

I2VA 和 FL2VA 都支持这个音色入口。控制器会把图片改写为 H3 reference 提示词，并显示实际后端 `ref2va_model`。提示词应直接写出角色、动作、镜头、对白和时间点；音色样本对应文本可填在“参考音频文本”。

“**Fish S2 高级音色锁定**”默认关闭。它先用 Fish S2 根据目标对白生成新对白音频，再把新音频送回 H3 reference。只有 Fish 模型就绪、确实需要改变对白内容时才打开；没有模型时请保持关闭。

## 性能预设

- **T2VA（无音色）**：显示“稳定质量”“质量优先加速”“质量优先二采样”“极速4步”“低显存”。极速 4 步使用官方 H3 Turbo LoRA；官方 T2V 示例支持该路线，建议先用 6-8 步确认画面，再降到 4 步。
- **I2VA / FL2VA / L2VA（无音色）**：显示“稳定质量”“质量优先加速”“质量优先二采样”“极速4步”“低显存”。极速 4 步使用 FL2VA 官方 Turbo LoRA。
- **REF2VA**：显示“稳定质量”“质量优先加速”“质量优先二采样”“参考图加速”“极速4步”“低显存”。参考图加速使用 Sage + EasyCache；极速 4 步使用官方 Ref2VA Turbo LoRA。
- **I2VA / FL2VA / L2VA + H3 原生音色参考**：自动走 H3 reference 后端，显示 REF2VA 兼容的六个预设；首尾图片改为提示词级参考，不再套用 FL2VA 硬端点语义。Fish S2 锁定模式会隐藏“质量优先二采样”。
- **质量优先加速**：保持原生 20 步，只启用 SageAttention，并使用 ComfyUI 动态分层加载；关闭 Turbo LoRA 与 EasyCache。它比 4 步慢，但画质最接近稳定质量，不需要额外下载模型；Sage 不可用时会保持原生 20 步，不会偷偷降到低步数。
- **质量优先二采样**：固定使用 H3 专用 latent 二采路线。8 步轨迹拆为前 6 步定结构和放大后的最后 2 步低噪细化；首阶段去噪 latent 的视频部分使用双线性插值按约 1.5 倍放大并对齐 H3 空间网格，再使用 CONST 专用重加噪继续采样。双线性插值不会像最近邻那样复制 latent 方块，2 步低噪尾段也不会大幅重画已经稳定的结构，可减少颗粒、油画纹理和细节漂移。两阶段都使用节点内置的 MiniMax H3 精确低峰值补丁：先释放已经消费的归一化输入，按独立 attention heads 分组计算，把结果写入已经消费的 Q 区域，并分块执行输出投影；MLP 也按 token 分块并复用输入，避免 15 秒 2K 二采一次申请约 2.81 GiB 注意力输出或约 11.24 GiB `fc1` 中间张量。不启用 Sage，不改变逐行 MLP 和独立 heads 的数学结果。整段视频不会进入 VideoVAE 解码/重编码。该档位强制搭配 RTX VSR，只允许 HIGH/ULTRA；2K 16:9 会以约 0.83 MP 首采，二采后 RTX VSR 约放大 1.36 倍。若模型结构不兼容或补丁没有确认成功，会在采样前自动回退为 8 步单采，避免首阶段完成后才显存溢出。该档位固定关闭 RIFE、保留原始 24 FPS，防止动态云雾和大视差建筑在合成中间帧时产生重影与柔化。
- **低显存**：8 步 + H3 内存高效 Sage，关闭 EasyCache，使用 ComfyUI 动态分层加载。插件会按时长自动降低 H3 原生采样尺寸；最终输出路线决定是否放大到目标尺寸。4/6/8/10/12/15 秒的原生上限约为 1.00/0.65/0.50/0.36/0.30/0.26 MP。
- **自定义**：仅为旧工作流和 API 保留，不在导演台普通预设下拉框显示。

## 最终输出与 AI 重建

在“生成规格”中选择唯一的“最终输出”路线，分辨率档位是最终保存视频的目标尺寸，不需要连接第二个放大节点：

- **原生尺寸直出**：保存 H3 实际生成尺寸；即使选择 2K/4K，也不会放大。
- **Lanczos 快速放大**：CPU 分块重采样，兼容性最好、显存占用低，但不会凭空重建细节。
- **AI 自动超分**：使用 `ComfyUI/models/upscale_models/` 中的通用模型逐帧重建细节。默认“自动选择”，会按目标倍率优先选择 X2/X4 模型；也可以在展开的“AI 超分模型”下拉框中指定已安装模型。模型缺失会在 H3 生成前报错。
- **AI 细节重建（RTX VSR）**：使用 NVIDIA RTX VSR；首次使用前需要安装其依赖和匹配驱动，节点会在生成前检查。目标与原生尺寸相同会自动旁路，目标更小会使用高质量缩小。

四条路线都只保存一个最终 MP4，不会同时输出原始视频和放大视频。放大只在解码后的帧上处理，不重新生成镜头时间线或对白内容。

### 运动平滑

- **关闭（默认，24 FPS）**：保留 H3 原始帧，不执行插帧，避免无需要时增加合成帧柔化和处理时间。
- **RIFE 2x（48 FPS）**：按相邻帧逐对生成中间帧，N 帧输出为 `2N-1` 帧。编码帧率同步翻倍，所以视频时长、对白时间和音频内容都不变；检测到真正硬切时会旁路插值，避免合成跨镜头鬼影。

RIFE 不是整段批量节点：它逐对推理并把帧流直接交给 RTX VSR，提前停止或编码失败时也会释放上游 RIFE 与下游 VSR 模型。启用前请从 [Comfy-Org 官方模型库](https://huggingface.co/Comfy-Org/frame_interpolation/resolve/main/frame_interpolation/rife_v4.26.safetensors) 下载 `rife_v4.26.safetensors`，放到 `ComfyUI/models/frame_interpolation/`；缺少模型会在 H3 采样前提示安装，不会等视频生成结束才报错。质量优先二采样不开放 RIFE，以避免大范围视差和动态云雾重影；低显存模式也不开放 RIFE，避免 8 GB 显卡因插帧模型与 H3/VSR 同时驻留而溢出。

### 最终音频

- **自动增强响度（默认）**：最终编码前提升过小的 H3 音轨，峰值目标为 -1.5 dBFS，最多提升 30 dB；静音保持静音，源 AUDIO 不会被原地修改。
- **保持原始响度**：不处理 H3 解码音频，适合后续在剪辑软件中自行混音。

RTX VSR 需要用户在 ComfyUI 自带 Python 中安装 DaSiWa requirements，并安装 NVIDIA Broadcast SDK：

```powershell
D:\ComfyUI_windows_portable-G313\python_embeded\python.exe -m pip install -r D:\ComfyUI_windows_portable-G313\ComfyUI\custom_nodes\ComfyUI-DaSiWa-Nodes\requirements.txt
```

切换模式或音色模式后，导演台会自动刷新可用预设。旧工作流如果保存了不适用的组合，会自动回退到“稳定质量”，并在警告输出中说明原因。

U10 中原有的 RTX/模型超分、水印和高级视频保存继续保留。U11 的“运动平滑”使用新的流式 RIFE 路径，不再调用 U10 那条会构造整段双倍帧批次的旧插帧链。整段二采已经内置到 `H3 专用 Latent 二采（自动旁路）` 节点，用户只需选择性能预设，不需要手动连接分支；其他预设自动执行原来的单采样路线。节点上保留的 VideoVAE 插口仅用于兼容旧 U11 JSON，质量优先二采样不会调用它。

## 分辨率与排版

导演台的“生成规格”是唯一生效的视频时长、画面比例和最终输出目标分辨率入口。左侧 Settings 中原有的 `resolution_preset`、`aspect_preset_when_not_image` 和 `swap_aspect_when_not_image` 已移除，避免两边设置不一致。H3 原生时长支持 4-15 秒整数。比例包含横向 `3:2`、`4:3`、`8:5`、`16:9`、`21:9`，对应竖向比例、`1:1` 和 `CUSTOM`；普通档位宽高按 32 对齐，`2K QHD` 和 `4K UHD` 目标保持精确的 2560×1440/3840×2160（竖向比例自动交换）。

这里的目标尺寸不是另一套需要手动配置的生成参数。低显存模式下，工作流自动执行 `H3 低分辨率采样 -> VAE 解码 -> 曝光保护 -> 原生/Lanczos/通用 AI/RTX VSR -> MP4 保存`；用户不需要连接节点。所有放大路线都按帧或小块处理，避免在显存中保留整段 2K/4K 视频。通用 AI 和 RTX VSR 会增强可恢复的边缘与纹理，但不会改变镜头时间线或重新生成内容。

“噪音种子”旁边可选择“固定、每次递增、每次递减、每次随机”。这是 ComfyUI 原生的生成后控制：当前任务使用当前显示的 seed，任务提交后再按所选模式准备下一次 seed。固定适合复现画面；递增/递减适合连续比较；随机适合批量探索。

U11 将主导演台、素材/路由、预览输出分为固定区域，上传槽保持两列规整排列，不需要手动连接图片或音频节点。导演台现有的快速设置、生成规格、导演与素材、音色参考、实际后端分区是稳定界面基线，后续功能优先在对应分区内扩展，不随意改变整体排列。
