# MiniMax H3 导演台 Plus 使用说明

## 先看本机状态

先运行工作流里的“本机能力状态”节点，或访问 `/h3-director-plus/status`。状态会分别列出 H3 FL2VA/REF2VA 基础模型、FL/Reference 训练型二采所需的精确 LoRA、3D latent 放大节点与模型、`H3SigmaRefiner`、Sage/EasyCache、RIFE 和 RTX VSR。Fish S2 必须同时满足节点和 `models/fishaudioS2/` 模型目录；只有节点、没有模型时会明确显示“模型未就绪”。RTX VSR 会在 `postprocess.rtx_vsr` 中单独显示依赖状态。插件不会静默下载模型。

## 模式选择

- **T2VA**：默认是纯文本生成视频，不需要图片；如果启用音色参考，会自动切换到 REF2VA 音频参考路线。
- **I2VA**：切换到 I2VA 后，在导演台内直接上传首帧图片。没有音色时使用 `fl2va_model`，首帧是硬约束；启用音色后自动改走 `ref2va_model`。
- **FL2VA**：切换到 FL2VA 后，在导演台内直接上传首帧和尾帧。没有音色时两张图是硬首尾帧；启用音色后两张图变成提示词级端点 reference。
- **L2VA**：切换到 L2VA 后，在导演台内直接上传尾帧图片，保持原生 H3 尾帧语义。
- **REF2VA**：切换后直接显示 9 个参考图槽。所有槽位地位相同，都是普通 reference 图（官方 Ref2VA 没有首尾帧语义，那是 FL2VA 的能力），角色、场景、服装、道具、风格或构图作用全部由提示词分配。编号与 `<Picture N>` 一一对应，必须从图 1 开始连续上传，不能跳号。只上传两张图时，可以在提示词中说明“从 `<Picture 1>` 的构图开始，最终落到 `<Picture 2>` 的构图”，但它们仍属于 reference 提示词约束，不是 FL2VA 硬端点。

## 音色参考

选择“**H3 原生音色参考**”，切换到支持音色的模式后，最多可上传 3 路参考音频。每一路先填写“对应角色”，再上传样本；提示词用 `<Audio 1>`、`<Audio 2>`、`<Audio 3>` 指定人物。音色也必须从 1 开始连续上传，不能跳号。示例：`角色甲使用 <Audio 1> 的音色说：“我们回家。”`。这条路线只提取音色、说话方式和表达特征，不复用上传音频的完整内容，也不会把原音频当作视频声音直接拼接。

音色模式下会出现“性别/音域约束”：样本是男声时选择“男声”，样本是女声时选择“女声”；“自动保持样本”只提供软约束。H3 原生参考不是严格声纹克隆，即使选了“男声”也只能降低性别漂移，不能保证完全像本人。需要尽量锁定上传者声线时，改用“**Fish S2 高级锁定**”，填写新的目标对白，并确认 Fish S2 模型已就绪；Fish 只使用音色参考 1。

T2VA、I2VA、FL2VA 和 L2VA 都支持这个音色入口。控制器会把图片改写为 H3 reference 提示词，并显示实际后端 `ref2va_model`。提示词应直接写出角色、动作、镜头、对白和时间点；音色样本对应文本可填在“参考音频文本”（填写后会以“仅用于音色对齐”的方式注入提示词，帮助模型对齐音色与说话内容）。

音色样本会在 H3 生成前做前置检查：官方允许每路 2–15 秒，低于 2 秒或超过 15 秒直接报错；2–5 秒、静音过多、音量过低或削波会给出警告。实测 5–10 秒干净单人声的音色锁定最稳。如果提示词本身已经是完整的 subject_definitions / detailed_description 结构，控制器会原样保留作者的角色与音色绑定，只补全缺失的 `<Audio N>` 绑定与参考音频文本，不再二次包装稀释。少步数路线（极速 4 步、低显存等）会显著削弱音色锁定与口型细节，出现警告时重要对白请改用“参考高清（原生20步）”或 Fish S2 高级锁定。

切换模式后，隐藏上传槽中的旧图片不会继续生效：T2VA 会清除首帧、尾帧和参考图，I2VA 只保留首帧，L2VA 只保留尾帧，FL2VA 只保留首尾帧。导演指南和日志会显示被忽略的残留素材。

“**Fish S2 高级音色锁定**”默认关闭。它先用 Fish S2 根据目标对白生成新对白音频，再把新音频送回 H3 reference。只有 Fish 模型就绪、确实需要改变对白内容时才打开；没有模型时请保持关闭。

## 性能预设

### 免费智能 1080p（默认）

“免费智能 1080p”是导演台和 API 模板的默认预设：本地免费执行，不调用付费云服务。显卡总显存 ≥20GB 且启动前空闲 ≥18GB、训练型二采依赖（turbo v4 LoRA + 3D latent 放大）就绪时，会自动启用训练型 latent 二采直出 1080p（U22 验证配方：8 步首采定结构 + 训练型 3D latent 放大 + 4 步低 sigma 重绘细节），不再多跑 SeedVR2/AI 超分；依赖或显存不满足时，普通显存保持 20 步采样并启用 SageAttention 加速，最终输出在已安装 SeedVR2 时默认使用 SeedVR2 扩散视频超分（单步扩散、整段一次处理，帧间时间一致性优于逐帧 GAN），未安装 SeedVR2 时回退到逐帧 AI 重建到至少 1080p，超分模型默认 `auto`，按实际放大倍率自动选择 X2/X4（≤2 倍优先 `RealESRGAN_x2plus.pth`，避免 X4 放大再缩回的算力浪费）；低显存设备仍使用 `RealESRGAN_x2plus.pth` X2 路线。生成阶段分辨率不等于最终输出分辨率：H3 先以显存安全的原生尺寸采样，再由后处理得到最终 MP4 尺寸。低显存二采最多 6 秒；启动前会检查空闲显存，无法满足时会在排队前给出原因。最终输出目标选择 2K QHD / 4K UHD 时，智能预设自动切换为训练型二采 + SeedVR2 扩散超分链：先按 U22 配方完成训练型 latent 二采，再由 SeedVR2 超分到最终 2K/4K 尺寸。该链要求训练型二采依赖与 SeedVR2 同时就绪，Fish S2 声纹锁定最高输出 1080p；20–24GB 显卡 2K 限 8 秒以内，4K 需要 28GB 以上显存，条件不满足会在排队前用中文给出具体原因。

REF2VA 现在与 FL 一样支持训练型 reference latent 二采：显存与依赖就绪时，免费智能 1080p 和质量优先二采样都会走 `trained_latent_ref`（turbo v4 LoRA + 训练型 3D latent 放大，8+4 步）。旧的 REF 二采配方（`minimax_h3_ref2v_turbo_4step` LoRA + `H3SigmaRefiner`）因生产灰屏已停用，旧工作流中保存的该状态只作为兼容标识，加载时会提示迁移，不会实际调用。Fish S2 锁定音色时仍然绕过二采，必须使用兼容的 reference 单采路线（`quality_sage`、`low_vram` 或 `ref_fast_4step`）。

- **T2VA / I2VA / FL2VA / L2VA（无音色）**：导演台只显示“免费智能 1080p”一个预设。它会按显存与依赖自动选路：≥20GB 且空闲 ≥18GB 时启用训练型 latent 二采直出 1080p（U22 配方 8+4 步，FL 后端走 `trained_latent_fl`），否则 20 步 SageAttention + SeedVR2 视频超分（无 SeedVR2 时自动回退免费 AI 超分并提示），低显存自动切换受限路线。原先的“质量优先加速”“质量优先二采样”“极速4步”转为 API/旧工作流兼容键。
- **REF2VA 或 H3 原生音色参考**：同样只显示“免费智能 1080p”。显存 ≥20GB 且空闲 ≥18GB、turbo v4 LoRA 就绪时自动走 `trained_latent_ref` 训练型二采直出 1080p，否则回退原生 20 步 + SageAttention + SeedVR2/AI 超分；原先的“参考高清（原生20步）”“参考极速（官方4步）”转为 API/旧工作流兼容键；Fish S2 继续使用兼容的 reference 流程。
- **T2VA / I2VA / FL2VA / L2VA + H3 原生音色参考**：自动走 H3 reference 后端，显示上述两项 REF2VA 兼容预设；首尾图片改为提示词级参考，不再套用 FL2VA 硬端点语义。
- **旧工作流兼容**：其他历史预设仍可由 API 和已保存节点加载，但不再出现在导演台的普通预设下拉框中。
- **质量优先加速**：保持原生 20 步，只启用 SageAttention，并使用 ComfyUI 动态分层加载；关闭 Turbo LoRA 与 EasyCache。它比 4 步慢，但画质最接近稳定质量，不需要额外下载模型；Sage 不可用时会保持原生 20 步，不会偷偷降到低步数。
- **质量优先二采样**：FL 后端使用 `trained_latent_fl` 的匹配 LoRA 和 3D latent 放大；REF2VA 后端使用 `trained_latent_ref`，由社区验证的 turbo v4 12 步 LoRA（U22 配方）驱动两段采样（8 步高 sigma 首采 + 4 步低 sigma 重绘），取代了因生产灰屏而停用的旧配方（ref2v 4 步 LoRA + `H3SigmaRefiner`，仅保留为旧工作流迁移/依赖识别信息，不会实际执行）。首采得到的 H3 AV latent 会分离音频与视频，音频原样保留；最终放大器只处理视频通道。第二阶段采样在检测到 `MMH3SplitUpscale`（`Comfyui_Minimax_h3_latent_Upscaler` 插件自带）时自动改为时间+空间分块采样：峰值显存只按单瓦片计，8GB 级显卡也能完成放大后的第二阶段；未安装该节点时自动回退整帧采样，行为与旧版一致。分块参数可用 guide 键覆盖（`split_tile_width/height` 默认 512，`split_chunk_frames` 默认 141，`split_seam_denoise` 默认 0.65），设置 `two_stage_tiled=False` 可强制整帧。最终 RTX 路线只执行一次 `HIGHBITRATE_ULTRA` VSR，`DEBLUR_LOW` 已停用；训练型二采固定关闭 RIFE、Sage 和 EasyCache，避免灰屏、颗粒、重影或跳帧。
- **低显存**：8 步 + H3 内存高效 Sage，关闭 EasyCache，使用 ComfyUI 动态分层加载。插件会按时长自动降低 H3 原生采样尺寸；最终输出路线决定是否放大到目标尺寸。4/6/8/10/12/15 秒的原生上限约为 1.00/0.65/0.50/0.36/0.30/0.26 MP。8–12GB 显存不执行训练型高分辨率二采，低显存不开放 4K，最终目标上限为 1080p。
- **低显存二采**：给 RTX 3070 8GB 级显卡单独开放的受限真二采，不是把高显存档强行解除拦截。1080p 支持 4–6 秒：4 秒保留约 0.46MP 首采和约 1.03MP 神经二采；5/6 秒按时长降低首采网格（约 0.37/0.31MP），用空间细节换时长，再由 `RealESRGAN_x2plus.pth` 逐帧重建到 FHD。最终目标超过 FHD 像素预算时自动回到“1080p FHD”。最终路线固定为单独的 `AI 自动超分`，不会再执行 RTX VSR，也不会把两个放大器叠加。整个采样阶段启用 ComfyUI LOW_VRAM，阶段间卸载 H3/放大模型，最终使用 CRF 16 并关闭 RIFE。启动前总显存须达到 8GB 级且至少有 6.0GB CUDA 空闲显存；缺少 X2 模型会在 H3 开始前提示。若“AI 超分模型”保持默认 `auto` 或仍为旧默认 `4x-UltraSharpV2.safetensors`，低显存二采会在生成前按实际倍率自动解析为 X2 模型并在警告中说明；手动指定其他 X4 模型仍会被拒绝。它比普通低显存明显更慢，且 1080p 是 AI 重建尺寸，不是 H3 原生 1080p 采样；7 秒以上仍会在采样前拒绝。
- **自定义**：仅为旧工作流和 API 保留，不在导演台普通预设下拉框显示。

### 官方 LightX2V LoRA 校验

极速 4 步及其他依赖官方 LightX2V LoRA 的性能档位，现由 ComfyUI 核心 `LoraLoaderModelOnly` 内置加载器应用。开始采样前会核对实际新增的模型补丁数；成功日志会包含 `patch_delta=<正整数>`。如果核心加载器抛错（例如文件损坏或格式不支持），或完全没有新增补丁，会在首个 H3 采样节点前停止；常见的缺文件、损坏文件和零补丁错误会包含解析后的 LoRA 文件名，不会把基础模型按 4/8 步继续生成。

### 训练型二采所需节点和模型

选择“质量优先二采样”或“低显存二采”前必须安装以下资产；导演台会在 H3 开始采样前检查，缺少任何一项都会直接给出中文文件名，不会跑到最后才报错：

- 训练型 3D latent 放大节点：[LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler)。必须使用包含长视频时间分块、重叠融合、宽高独立 32 对齐和执行后卸载模型的新版本。
- 放大模型 `minimax_h3_latent_upscaler_3d_bf16.safetensors`，放到 `ComfyUI/models/latent_upscale_models/`。
- FL 路线 LoRA：`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` 与 `minimax_h3_fl2v_turbo_4step_v1.1_768p_comfyui_bf16.safetensors`，放到 `ComfyUI/models/loras/`。
- Reference 路线 LoRA：`minimax_h3_turbo_v4_step600_ema.safetensors`（或其 ComfyUI 转换版 `minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors`，两者任一即可），放到 `ComfyUI/models/loras/`。旧配方的 `minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors` 与 [ComfyUI-YCNodes-MiniMax-H3](https://github.com/yichengup/ComfyUI-YCNodes-MiniMax-H3) 的 `H3SigmaRefiner` 仅为旧工作流迁移识别保留，新二采不再使用。

AutoDL/Linux 无需 `git` 的安装方式：

```bash
cd /root/ComfyUI
mkdir -p custom_nodes models/latent_upscale_models models/loras
wget -O /tmp/h3-latent-upscaler.zip https://codeload.github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler/zip/refs/heads/main
python -c "import zipfile; zipfile.ZipFile('/tmp/h3-latent-upscaler.zip').extractall('/root/ComfyUI/custom_nodes')"
wget -O /tmp/h3-sigma.zip https://codeload.github.com/yichengup/ComfyUI-YCNodes-MiniMax-H3/zip/refs/heads/main
python -c "import zipfile; zipfile.ZipFile('/tmp/h3-sigma.zip').extractall('/root/ComfyUI/custom_nodes')"
python -m pip install --no-cache-dir --no-deps --index-url https://pypi.org/simple "huggingface-hub==0.36.0"
hf download LBH-123-AI/Minimax_h3_latent_Upscaler minimax_h3_latent_upscaler_3d_bf16.safetensors --local-dir /root/ComfyUI/models/latent_upscale_models
hf download lightx2v/Minimax-h3-Turbo minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors minimax_h3_fl2v_turbo_4step_v1.1_768p_comfyui_bf16.safetensors minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors --local-dir /root/ComfyUI/models/loras
hf download larryvrh/MiniMax-H3-Turbo-Lora minimax_h3_turbo_v4_step600_ema.safetensors --local-dir /root/ComfyUI/models/loras
```

如果 `huggingface.co` 被墙，先 `export HF_ENDPOINT=https://hf-mirror.com` 再执行上面的 `hf download`。turbo v4 也可以改用 drbaph 的 ComfyUI 转换版（U22 工作流同款，与原版二选一）：

```bash
hf download drbaph/MiniMax-H3-Turbo-Lora-ComfyUI minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors --local-dir /root/ComfyUI/models/loras
```

不要执行无版本上限的 `pip install -U huggingface_hub`；当前 ComfyUI 使用的 Transformers 要求 `huggingface-hub>=0.34.0,<1.0`。AutoDL 的全局 pip 配置可能强制使用尚未同步兼容版本的镜像，因此恢复命令显式指定官方 PyPI，并用 `--no-deps` 避免改动其他 ComfyUI 依赖：

```bash
/root/miniconda3/bin/python -m pip install --no-cache-dir --force-reinstall --no-deps --index-url https://pypi.org/simple "huggingface-hub==0.36.0"
/root/miniconda3/bin/python -c "import huggingface_hub, transformers; print(huggingface_hub.__version__, transformers.__version__)"
```

如果 `pypi.org/simple` 也无法访问，可以直接安装 PyPI 官方通用 wheel，完全绕过包索引：

```bash
/root/miniconda3/bin/python -m pip install --no-cache-dir --force-reinstall --no-deps "https://files.pythonhosted.org/packages/cb/bd/1a875e0d592d447cbc02805fd3fe0f497714d6a2583f59d14fa9ebad96eb/huggingface_hub-0.36.0-py3-none-any.whl"
```

安装后重启 ComfyUI，再查看“能力与模型状态”。训练型放大器的官方说明明确指出：它节省首阶段生成时间，但高分辨率二采本身仍会占用接近直接高分辨率采样的峰值显存；因此 U11 不会把“有放大模型”误当成“无限省显存”。

## 最终输出与 AI 重建

在“生成规格”中选择唯一的“最终输出”路线，分辨率档位是最终保存视频的目标尺寸，不需要连接第二个放大节点：

- **SeedVR2 视频超分（默认且唯一推荐）**：调用已安装的 ComfyUI-SeedVR2_VideoUpscaler 节点，用字节 SeedVR2 单步扩散模型对整段视频一次性超分，是 AI 生成内容清晰度基准的第一名，帧间时间一致性优于逐帧 GAN，是“免费智能 1080p”和“质量优先二采样”的唯一可见路线。按显存自动分档并优先选择 7B sharp 变体：约 36GB 及以上使用 `seedvr2_ema_7b_sharp_fp16` 全量无交换；约 20–36GB 使用 `seedvr2_ema_7b_sharp_fp8_e4m3fn_mixed_block35_fp16`（或 Q4_K_M GGUF）+ CPU offload + block swap + VAE 分块；未安装 7B 时自动回退 3B 权重（约 20GB 级 fp8 全量、12–20GB fp8 + 少量 block swap、约 12GB 及以下 Q4_K_M GGUF + 激进交换 + 小批帧）。权重需放入 `ComfyUI/models/SEEDVR2/`（`seedvr2_ema_7b_sharp_*` 或 `seedvr2_ema_3b_*` DiT 与 `ema_vae_fp16.safetensors`）；节点或权重缺失时不再中断生成，而是自动回退到“AI 自动超分”并在警告中列出缺失项与安装方式。
- **AI 自动超分（SeedVR2 未就绪时的自动回退）**：使用 `ComfyUI/models/upscale_models/` 中的通用模型逐帧重建细节。默认 `auto` 按目标倍率自动挑选 X2/X4 模型（≤2 倍优先 X2，避免 X4 放大再缩回的浪费；无 X2 时回退 X4 并给出警告）；也可以在展开的“AI 超分模型”下拉框中指定其他已安装模型。模型缺失会在 H3 生成前报错。
- **原生尺寸直出 / Lanczos 快速放大 / AI 细节重建（RTX VSR）**：仅为兼容旧工作流与旧 API 载荷保留，不在导演台“最终输出”选择器中展示。RTX VSR 首次使用前需要安装其依赖和匹配驱动，节点会在生成前检查；目标与原生尺寸相同会自动旁路，目标更小会使用高质量缩小。
- **参考图尺寸策略**：`match` 会把角色参考图压缩到生成阶段分辨率，最终放大超过 1.5 倍时控制器会警告身份细节损失；重要角色镜头建议改为 `max`（保留约 2048px 短边，耗时和显存略增）。

所有路线都只保存一个最终 MP4，不会同时输出原始视频和放大视频。放大只在解码后的帧上处理，不重新生成镜头时间线或对白内容。

两个训练型二采预设的最终 H.264 都使用 CRF 16；若输出节点原本设为 0–15，则保留更高质量值。编码完成后会以 stream-copy 无损写入 BT.709 limited-range 标记，视频帧和音频都不会再次编码；即使标记步骤失败，也会保留已经成功生成的 MP4 并在日志中明确提示。其他性能预设继续使用各自原有编码值。

导演台显示的三个尺寸含义不同：`H3首采` 是扩散模型第一阶段的实际画布；`神经latent二采` 是训练型放大并低 sigma 重绘后的真实细节基准；`最终输出` 才是 MP4 的像素尺寸。高显存档位的 2K 16:9 通常为约 `1280×704 -> 1920×1056 -> 2560×1440`，最后 SeedVR2 只做约 1.33–1.36 倍扩散重建，不再从约 0.2 MP 硬拉到 2K；`1920×1056不是原生2K`，而是神经二采后的细节基准。4K 为 `约1080p神经二采基准 -> 3840×2160 SeedVR2 扩散超分`；4K 不是 H3 原生采样。最终文件仍须用媒体属性或 `ffprobe` 验证为 2560×1440 / 3840×2160，像素尺寸达到 2K/4K 不等于源细节天然就是原生 2K/4K。

训练型二采和单次扩散/RTX 后处理会增加额外时间，但不提高 H3 显存峰值；输入输出会先做等比中心裁切，随机种子仍影响生成纹理。

28GB 及以上显存且启动前至少有 24GB 空闲显存时，选择“质量优先二采样 + 1080p FHD”会自动启用 **1080p 平衡二采**：判定空闲显存前会先自动卸载缓存模型释放显存（日志打印“采样前已自动释放缓存模型：空闲显存 XGB -> YGB”，可用 `MMH3_SMART_PREFREE=0` 关闭），避免长会话因模型常驻被误判降级到 20 步 + SeedVR2 慢速路线；本次运行所需模型仍会在采样时按需重载。横向为 `960×544 -> 1920×1088 -> 1920×1080`，竖向为对应旋转尺寸。首采 0.5MP、训练型 latent 放大 2.0 倍（官方 H3 latent 放大器的训练倍率，U22 工作流验证配方），最后先等比中心裁切约 0.7% 的边缘，再用分块 Lanczos 缩小，不执行 RTX VSR，也不需要 NVIDIA VFX 依赖。两个采样阶段默认都叠加 KJNodes 的 H3 内存高效 SageAttention 补丁（U22 验证配方，每步耗时从数十秒降到个位数秒）。**底模必须使用 U22 验证的 INT8 混合模型 `minimax/minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors`**（FL2VA/REF2VA 通用）：pruned convrot/nvfp4 重量化底模（如 `minimax_h3_ref2va_pruned_int8_convrot.safetensors`）在 SageAttention 的 INT8/FP8 核下会产生全画面编织状纹路并给音频带入杂质，实测只有混合底模干净。REF2VA 路线还会在 turbo v4 之后自动叠加四个社区 LoRA，全部为“已安装才叠加、未安装只记日志跳过”：U22 细节链 `wushu_spatial_physics_v2_1000_pruned.safetensors`@0.3 与 `MysticXXX_MMH3-V1.safetensors`@0.5（可用环境变量 `MMH3_DETAIL_LORAS=0` 关闭），以及追加链 `动作连续性修复LORA.safetensors`（兼容文件名 `动作i连续性修复LORA.safetensors`）@0.4 与 `MinimaxH3真实电影质感V1.0.safetensors`（兼容 `MinimaxH3真实电影质感V0.1.safetensors`）@0.5（可用环境变量 `MMH3_EXTRA_LORAS=0` 单独关闭）。也可以在画布上的“兼容加速路由”节点（MiniMaxH3AccelerationRouter，默认折叠）里用“community_loras / 社区 LoRA”下拉框直接切换：全部自动叠加（默认）/ 仅 U22 细节链 / 全部关闭；节点控件与环境变量任一关闭都会生效。追加链的 0.4/0.5 是保守初始强度，若画面出现过锐、油腻、规则颗粒纹或色彩偏移，先把开关切到“仅 U22 细节链”做对照再逐项回调。SageAttention 环境变量矩阵：默认双阶段全开（最快，配混合底模干净）；`MMH3_SECOND_STAGE_SAGE=0` 保留一采 Sage、二采改全精度（更慢，仅作对照）；`MMH3_TWO_STAGE_SAGE=0` 完全关闭（仍用 convrot 底模时的保底干净路线，最慢）。与保守 FHD 网格相比，神经二采像素增加约 3%，但仍保留 FL/Reference 8+4 步（12 步 SplitSigmas 切分）、原视频时长和原音频。

20–24GB 级显卡，或 28GB+ 显卡因刚取消任务只剩 18–24GB 空闲显存时，会自动切换为 **1080p 保守 FHD 二采**：横向为 `1280×704 -> 1920×1056 -> 1920×1080`，竖向为对应旋转尺寸。它至少需要 18GB 空闲显存，最终只做轻量中心裁切与 Lanczos 对齐，同样不执行 RTX VSR。这个放宽只适用于精确 1080p FHD；2K/4K 仍使用原来的高显存门槛，不会套用 FHD 预算。日志与导演台 warning 会明确显示实际命中的链路。

### 上传素材的移除

已上传图片或音频会显示“更换”和“移除”。移除只清空节点的隐藏 widget、刷新预览并标记画布为 dirty，不调用删除 API，因此“移除只取消节点引用，不删除原文件”。REF2VA 删除中间图片后，后续槽位会向前补位，并提示检查 `<Picture N>`；音色音频会和 `voice_reference_name_1..3` 一起补位，并提示检查 `<Audio N>` 与角色名。I2VA/FL2VA/L2VA 的首帧和尾帧是独立槽位，清空其中一个不会改变另一个。

### 运动平滑

- **关闭（默认，24 FPS）**：保留 H3 原始帧，不执行插帧，避免无需要时增加合成帧柔化和处理时间。
- **RIFE 2x（48 FPS）**：按相邻帧逐对生成中间帧，N 帧输出为 `2N-1` 帧。编码帧率同步翻倍，所以视频时长、对白时间和音频内容都不变；检测到真正硬切时会旁路插值，避免合成跨镜头鬼影。

RIFE 不是整段批量节点：它逐对推理并把帧流直接交给 RTX VSR，提前停止或编码失败时也会释放上游 RIFE 与下游 VSR 模型。启用前请从 [Comfy-Org 官方模型库](https://huggingface.co/Comfy-Org/frame_interpolation/resolve/main/frame_interpolation/rife_v4.26.safetensors) 下载 `rife_v4.26.safetensors`，放到 `ComfyUI/models/frame_interpolation/`；缺少模型会在 H3 采样前提示安装，不会等视频生成结束才报错。两个训练型二采预设都不开放 RIFE，以避免重影和额外显存峰值；普通低显存模式也不开放 RIFE。

### 最终音频

- **自动增强响度（默认）**：最终编码前提升过小的 H3 音轨，峰值目标为 -1.5 dBFS，最多提升 30 dB；静音保持静音，源 AUDIO 不会被原地修改。
- **保持原始响度**：不处理 H3 解码音频，适合后续在剪辑软件中自行混音。

使用 RTX VSR 前，必须在当前 ComfyUI Python 中安装官方 `nvidia-vfx` wheel；以下 DaSiWa requirements 安装命令可保留为依赖安装入口：

```powershell
D:\ComfyUI_windows_portable-G313\python_embeded\python.exe -m pip install -r D:\ComfyUI_windows_portable-G313\ComfyUI\custom_nodes\ComfyUI-DaSiWa-Nodes\requirements.txt
```

Linux 请使用 NVIDIA VSR 支持驱动分支 `570.190+`、`580.82+` 或 `590.44+`，不要求安装 Windows NVIDIA Broadcast SDK。Windows 请检查 NVIDIA 驱动、官方 `nvidia-vfx` wheel 与 NVIDIA Broadcast SDK/Video Effects 运行库兼容。导演台会在 H3 开始前，以真实 `640×360 → 1280×720` 单帧执行一次 RTX VSR `load + run`；失败会提前停止，不会在视频生成后才报错。

切换模式或音色模式后，导演台会自动刷新可用预设。旧工作流如果保存了不适用的组合，会自动回退到“稳定质量”，并在警告输出中说明原因。

U11 的“运动平滑”使用流式 RIFE 路径，不调用会构造整段双倍帧批次的旧插帧链。训练型二采已内置到 `H3 训练型 3D Latent 二采（自动旁路）` 节点，用户只需选择性能预设，不需要手动连接分支；其他预设自动执行单采样路线。二采节点不再保留 VideoVAE 输入，也不会执行整段 VAE 解码、图像放大、再编码的高内存往返。

## 分辨率与排版

导演台的“生成规格”是唯一生效的视频时长、画面比例和最终输出目标分辨率入口。左侧 Settings 中原有的 `resolution_preset`、`aspect_preset_when_not_image` 和 `swap_aspect_when_not_image` 已移除，避免两边设置不一致。H3 原生时长支持 4-15 秒整数。比例包含横向 `3:2`、`4:3`、`8:5`、`16:9`、`21:9`，对应竖向比例、`1:1` 和 `CUSTOM`；普通档位宽高按 32 对齐，`1080p FHD`、`2K QHD` 和 `4K UHD` 在 16:9 下保持精确的 1920×1080、2560×1440、3840×2160（9:16 自动交换）。

这里的目标尺寸不是另一套需要手动配置的生成参数。低显存模式下，工作流自动执行 `H3 低分辨率采样 -> VAE 解码 -> 曝光保护 -> 选中的单一后处理 -> MP4 保存`；用户不需要连接节点。8–12GB 低显存档位最高开放 1080p，不允许以极低源分辨率硬拉 4K。其他档位的放大路线都按帧或小块处理，避免在显存中保留整段 2K/4K 视频；通用 AI 和 RTX VSR 只增强可恢复的边缘与纹理，不改变镜头时间线或重新生成内容。

“噪音种子”旁边可选择“固定、每次递增、每次递减、每次随机”。这是 ComfyUI 原生的生成后控制：当前任务使用当前显示的 seed，任务提交后再按所选模式准备下一次 seed。固定适合复现画面；递增/递减适合连续比较；随机适合批量探索。

U11 将主导演台、素材/路由、预览输出分为固定区域，上传槽保持两列规整排列，不需要手动连接图片或音频节点。导演台现有的快速设置、生成规格、导演与素材、音色参考、实际后端分区是稳定界面基线，后续功能优先在对应分区内扩展，不随意改变整体排列。
