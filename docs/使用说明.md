# MiniMax H3 导演台 Plus 使用说明

## 2026-10：采样和超分选项精简

新建工作流默认使用稳定质量采样和 VOSR2 输出。采样菜单保留稳定 20 步、训练型 8+4 二采、低显存 20 步动态卸载；参考生成会显示专用的参考高清 20 步档。Fish S2 隐藏不兼容的训练型二采。最终超分菜单只显示 VOSR2、SeedVR2 和 AI 超分（RealESRGAN X2）。旧工作流和 API 仍接受旧选项，但导演台不再展示它们。

低显存设备至少有一条可用路线：选择“低显存”采样和“AI 超分”，工作流固定解析为 X2 模型并逐帧处理；如果没有安装 X2，会在 H3 采样前提示，不会回退到显存开销更大的 X4。普通显存可在 RTX VSR 路线选择 RIFE 2x 输出 48 FPS；VOSR2 保持 24 FPS。最终尺寸、画质、显存峰值与速度仍需在目标 AutoDL 显卡上实测；单元测试不能代替视频对照。

## 先看本机状态

先运行工作流里的“本机能力状态”节点，或访问 `/h3-director-plus/status`。状态会分别列出 H3 FL2VA/REF2VA 基础模型、FL/Reference 训练型二采所需的精确 LoRA、3D latent 放大节点与模型、`H3SigmaRefiner`、Sage/EasyCache、RIFE 和 RTX VSR。Fish S2 必须同时满足节点和 `models/fishaudioS2/` 模型目录；只有节点、没有模型时会明确显示“模型未就绪”。RTX VSR 会在 `postprocess.rtx_vsr` 中单独显示依赖状态。插件不会静默下载模型。

## 模式选择

- **T2VA**：默认是纯文本生成视频，不需要图片；如果启用音色参考，会自动切换到 REF2VA 音频参考路线。
- **I2VA**：切换到 I2VA 后，在导演台内直接上传首帧图片。没有音色时使用 `fl2va_model`，首帧是硬约束；启用音色后自动改走 `ref2va_model`。
- **FL2VA**：切换到 FL2VA 后，在导演台内直接上传首帧和尾帧。没有音色时两张图是硬首尾帧；启用音色后两张图变成提示词级端点 reference。
- **L2VA**：切换到 L2VA 后，在导演台内直接上传尾帧图片，保持原生 H3 尾帧语义。
- **REF2VA**：切换后直接显示 9 个参考图槽。所有槽位地位相同，都是普通 reference 图（官方 Ref2VA 没有首尾帧语义，那是 FL2VA 的能力），角色、场景、服装、道具、风格或构图作用全部由提示词分配。编号与 `<Picture N>` 一一对应，必须从图 1 开始连续上传，不能跳号。只上传两张图时，可以在提示词中说明“从 `<Picture 1>` 的构图开始，最终落到 `<Picture 2>` 的构图”，但它们仍属于 reference 提示词约束，不是 FL2VA 硬端点。

## 音色参考

“**H3 原生音频参考**”遵循 H3 的 `ref_audios` 条件输入：最多上传 3 段，按 `<Audio 1>` 到 `<Audio 3>` 绑定角色。输入的是整段参考音频，H3 可能复现其中的语音内容；它不是只抽取音色的克隆器，也不会把原文件直接接到最终音轨。若只要克隆音色并生成新对白，选择 Fish S2 并在“目标对白”中明确填写新台词；若要原样使用上传音频的内容，选择“完整复用上传音频”，上传的一整段会直接成为成片音轨，不送入 H3 条件。

多角色对白中的 `(S1)`、`(S2)` 按角色首次发声顺序分配，不能照抄 `<Subject N>` 的人物顺序，也不能照抄 `<Audio N>` 上传槽位。`<Subject N>`、`(Sx)` 和 `<Audio N>` 是三套独立编号：如果南宫阙是 `<Subject 2>`、使用第二路音频并且最先开口，正确写法是 `南宫阙 <Subject 2> (S1) 使用 <Audio 2> 的音色说：<d>[Chinese] ...</d>`。导演台会在生成前检查可识别的多角色对白顺序，避免错误编号导致音色串位。

两路及以上 H3 原生音色属于模型高风险场景：MiniMax 已公开多人参考音色可能出现串色，即使轮流发声也不保证严格克隆。每句只允许一个人说话，句间留 0.6–1.0 秒无声反应；在每个对白段重复角色、`<Subject N>`、`(Sx)`、`<Audio N>` 和 `<d>`，并明确其他角色闭嘴、无口型、无轻笑或哼唱。不要让台词跨切镜，不要加入带人声的 BGM。15 秒内三人最好各一句短台词；更多轮次使用多个生成单元后期合成音轨。

H3 原生参考下会出现“性别/音域约束”，它是 H3 生成条件中的软约束，不是严格声纹克隆。Fish S2 模式只用第一路样本克隆音色，按“目标对白”生成新音频；该音频用于 H3 口型条件并替换生成视频的音轨。它不会从时间轴提示词中抽取台词。Fish 失败会报错，不会静默回退。完整复用模式保留上传音频整段内容作为最终音轨；音频编码为 MP4 音轨时会经过容器编码。

T2VA、I2VA、FL2VA 和 L2VA 都支持这个音色入口。控制器会把图片改写为 H3 reference 提示词，并显示实际后端 `ref2va_model`。提示词应直接写出角色、动作、镜头、对白和时间点；音色样本对应文本可填在“参考音频文本”（填写后会以“仅用于音色对齐”的方式注入提示词，帮助模型对齐音色与说话内容）。

音色样本会在 H3 生成前做前置检查：官方允许每路 2–15 秒，低于 2 秒或超过 15 秒直接报错；2–5 秒、静音过多、音量过低或削波会给出警告。实测 5–10 秒干净单人声的音色锁定最稳。通过检查后，各路 H3 样本统一为单声道 32 kHz，并以线性增益校准到约 -22 dBFS、峰值不高于 -3 dBFS；不压缩、不裁切、不改变时长。导演日志会记录每个 `voice_slot` 的角色、来源文件和校准数据。如果提示词本身已经是完整的 subject_definitions / detailed_description 结构，控制器会原样保留作者的角色与音色绑定，只补全缺失的 `<Audio N>` 绑定与参考音频文本，不再二次包装稀释。少步数路线（极速 4 步、低显存等）会显著削弱音色锁定与口型细节，出现警告时重要对白请改用“参考高清（原生20步）”或 Fish S2 高级锁定。

切换模式后，隐藏上传槽中的旧图片不会继续生效：T2VA 会清除首帧、尾帧和参考图，I2VA 只保留首帧，L2VA 只保留尾帧，FL2VA 只保留首尾帧。导演指南和日志会显示被忽略的残留素材。

Fish S2 模式需要已安装 Fish 节点和模型，并且必须填写“目标对白”。参考音频文本用于提供样本原文，避免克隆时把样本里的台词当作新台词。

## 性能预设

- **稳定质量**：标准 T2VA/I2VA/FL2VA/L2VA 使用原生 20 步；REF2VA 和 H3 音色参考使用参考专用原生 20 步。
- **质量优先二采样**：首采 8 步、训练型 latent 放大后再以 4 步重绘。Fish S2 路线不显示该选项。二采不能与 RIFE 组合。
- **低显存**：原生 20 步，使用动态分层加载并按时长降低采样尺寸；选择 AI 超分时只使用 X2 模型，逐帧处理以限制显存峰值。低显存固定关闭 RIFE。
- **旧工作流兼容**：旧的智能、快速、RTX VSR、Lanczos 等 API/工作流值继续由后端接受；新导演台菜单只展示当前路线的三种采样方案和三种视频超分方案。

最终输出目标可以选择 768p H3、1080p FHD、2K QHD 或 4K UHD。输出方法会严格按选择执行：VOSR2 使用 TE-Speed-VOSR2，SeedVR2 使用 SeedVR2 视频超分，AI 超分使用 ComfyUI 已安装的图像超分模型。选择的节点或模型缺失时会在 H3 采样前报错，不会换成另一个引擎。若 H3/二采结果已达到或超过目标尺寸，工作流直接按目标尺寸缩放，不会为了“超分”再放大后缩回。

低显存至少可使用“低显存 + AI 超分”。请在 `ComfyUI/models/upscale_models/` 安装 `RealESRGAN_x2plus.pth`；选择 `auto` 时后端优先解析为可用 X2，若只找到 X4，会在采样前明确提示。8GB 级设备建议先用 768p 短片验证；2K/4K 的显存峰值、速度、画质和系统内存占用需要按实际 GPU 实测。具体时长预算见 [交付说明](U11清晰度增强版交付说明.md)。

### 官方 LightX2V LoRA 校验

极速 4 步及其他依赖官方 LightX2V LoRA 的性能档位，现由 ComfyUI 核心 `LoraLoaderModelOnly` 内置加载器应用。开始采样前会核对实际新增的模型补丁数；成功日志会包含 `patch_delta=<正整数>`。如果核心加载器抛错（例如文件损坏或格式不支持），或完全没有新增补丁，会在首个 H3 采样节点前停止；常见的缺文件、损坏文件和零补丁错误会包含解析后的 LoRA 文件名，不会把基础模型按 4/8 步继续生成。

### 训练型二采所需节点和模型

选择“质量优先二采样”或“低显存二采”前必须安装以下资产；导演台会在 H3 开始采样前检查，缺少任何一项都会直接给出中文文件名，不会跑到最后才报错：

- 训练型 3D latent 放大节点：[LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler)。必须使用包含长视频时间分块、重叠融合、宽高独立 32 对齐和执行后卸载模型的新版本。
- 放大模型 `minimax_h3_latent_upscaler_3d_bf16.safetensors`，放到 `ComfyUI/models/latent_upscale_models/`。
- FL 路线 LoRA：`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` 与 `minimax_h3_fl2v_turbo_4step_v1.1_768p_comfyui_bf16.safetensors`，放到 `ComfyUI/models/loras/`。
- Reference 路线 LoRA：`minimax_h3_turbo_v4_step600_ema.safetensors`（或其 ComfyUI 转换版 `minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors`，两者任一即可），放到 `ComfyUI/models/loras/`。旧配方的 `minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors` 与 [ComfyUI-YCNodes-MiniMax-H3](https://github.com/yichengup/ComfyUI-YCNodes-MiniMax-H3) 的 `H3SigmaRefiner` 仅为旧工作流迁移识别保留，新二采不再使用。

### U24 文武双修增强（可选）

高显存 REF2VA 二采会沿用 U22 的 `wushu_spatial_physics_v2_1000_pruned.safetensors`@0.3 与 `MysticXXX_MMH3-V1.safetensors`@0.5；同时会在已安装时追加 U24 风格的动作链：`Motion_Repair.safetensors`@0.4、`H3_Combat_V2.safetensors`@0.35、10ErosMax T8 LoRA@0.25，以及电影质感 LoRA@0.5。所有追加项都是可选项，缺失只记录日志，不会阻止生成；可用 `MMH3_EXTRA_LORAS=0` 关闭追加链，或在兼容加速路由节点中选择“仅 U22 细节链”。`H3_Combat_V2.safetensors` 与 `Motion_Repair.safetensors` 分别来自 [MiniMax-H3-Combat-Base-V2](https://huggingface.co/JOKER141/MiniMax-H3-Combat-Base-V2) 和 [MiniMax-H3-General-Motion-Continuity-Repair](https://huggingface.co/JOKER141/MiniMax-H3-General-Motion-Continuity-Repair)。

可用 `python tools/install_u24_assets.py --comfy /path/to/ComfyUI --list` 查看已登记的公开下载地址；实际下载后脚本会打印每个文件的 SHA256，便于在高显存机器上复核。中文电影质感文件名和 MysticXXX 文件目前没有可靠公开校验源，脚本不会把它们伪装成已验证依赖。

## 最终输出与 AI 重建

最终输出档位是 MP4 的目标尺寸：横屏 2K QHD 为 2560×1440，4K UHD 为 3840×2160；竖屏交换宽高。4K 不是 H3 原生采样，而是由所选后处理路线完成最终重建。生成阶段分辨率不等于最终输出分辨率，像素尺寸达到 2K/4K 不代表源细节天然就是原生 2K/4K。

放大菜单只提供三个明确路线，选中后严格执行；所选节点或模型缺失会在 H3 采样前报错，不会静默切换到另一种引擎：

- **VOSR2**：使用已安装的 TE-Speed-VOSR2 节点处理视频帧，保持 H3 原始 24 FPS。VOSR2 不叠加 RIFE，避免把超分工作量翻倍而没有增加源细节。
- **SeedVR2**：使用 ComfyUI-SeedVR2_VideoUpscaler 节点及其已安装权重做视频超分。该路线可能明显增加耗时和显存占用，需按目标 AutoDL 显卡实测；未安装时直接报错，不会改用 AI 超分。
- **AI 超分**：使用 ComfyUI 本地免费图像超分模型逐帧重建细节。普通显存按目标倍率解析已安装模型；低显存模式固定使用 RealESRGAN X2，并且每次只处理一帧。低显存缺少 X2 时会在采样前提示，不会换成 X4。

低显存档面向约 8–12GB 显卡，最终输出最高为 1080p，低显存不开放 4K。选择 1080p 时，历史 smart_free_1080p API 路线最多 6 秒，并要求启动前有足够空闲显存；当前低显存菜单路线也会按最终尺寸和视频时长做前置预算检查。低显存至少有一条可用组合：选择低显存采样和 AI 超分，并安装 RealESRGAN_x2plus.pth。768p 短片适合先在 AutoDL 上验证显存峰值与画质。

稳定质量采样保持 H3 原生 20 步。质量优先二采样执行 8 步首采、训练型 latent 放大和 4 步低 sigma 重绘；H3 原生音频参考支持训练型 reference latent 二采，二采期间保护音频分支并在完成后精确回填首采音频。H3 原生音色参考的 REF2VA 路线可使用此能力。该模式需要相应训练型节点、模型和足够显存；Fish S2 不开放此采样方案。质量二采会增加额外时间，但不提高 H3 显存峰值；输入输出等比中心裁切，随机种子仍影响生成纹理。

两个训练型二采预设的最终 H.264 使用 CRF 16；若输出节点原本设为 0–15，则保留更高质量值。编码完成后会以 stream-copy 无损写入 BT.709 limited-range 标记，视频帧和音频都不会再次编码；即使标记步骤失败，也会保留已经成功生成的 MP4 并在日志中明确提示。

导演台显示的三个尺寸含义不同：H3 首采是扩散模型第一阶段的实际画布，神经 latent 二采是训练型放大并低 sigma 重绘后的细节基准，最终输出才是 MP4 像素尺寸。高显存 2K 路线的参考尺寸可为 1280×704 -> 1920×1056 -> 2560×1440；1920×1056不是原生2K。4K 由所选超分引擎完成最后一级，不是 H3 原生 4K 采样。最终文件应使用媒体属性或 ffprobe 验证尺寸；实测速度、人物运动清晰度和显存峰值仍需用同种子短片在目标 GPU 上对照。

旧版实验性的 DEBLUR_LOW 双效果链已停用，避免真实运行中出现彩条和花屏。RTX VSR 旧路线只为历史工作流兼容保留，不在新菜单中展示；旧工作流/API 中的原生直出、Lanczos、RTX VSR 等值仍由后端按兼容逻辑处理。历史 RTX VSR 的最高保真质量档名称为 HIGHBITRATE_ULTRA。

28GB 及以上显卡且启动前至少有 24GB 空闲显存时，选择“质量优先二采样 + 1080p FHD”会自动启用 1080p 平衡二采样：判定空闲显存前先卸载缓存模型，避免长会话因模型常驻而误判；本次运行所需模型会在采样时按需重载。横向参考尺寸为 1280×704 -> 1920×1056 -> 1920×1080，训练型 latent 放大约 1.5 倍，最后中心裁切并用 Lanczos 对齐，不执行 RTX VSR。实际路线和显存预算以运行日志为准。

20–24GB 级显卡，或 28GB 以上显卡因刚取消任务只剩 18–24GB 空闲显存时，1080p 保守 FHD 二采会使用对应的保守路线：横向参考尺寸为 1280×704 -> 1920×1056 -> 1920×1080，至少需要 18GB 空闲显存；最终只做轻量中心裁切与 Lanczos 对齐。此预算只适用于精确 1080p FHD，不用于 2K/4K。

AutoDL/Linux 安装训练型 latent 放大器的命令和模型下载方式见下方“训练型二采所需节点和模型”。其中 3D latent 放大节点可从 codeload.github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler 下载，模型可使用 hf download LBH-123-AI/Minimax_h3_latent_Upscaler 获取。

### 上传素材的移除

已上传图片或音频会显示“更换”和“移除”。移除只清空节点的隐藏 widget、刷新预览并标记画布为 dirty，不调用删除 API，因此“移除只取消节点引用，不删除原文件”。REF2VA 删除中间图片后，后续槽位会向前补位，并提示检查 `<Picture N>`；音色音频会和 `voice_reference_name_1..3` 一起补位，并提示检查 `<Audio N>` 与角色名。I2VA/FL2VA/L2VA 的首帧和尾帧是独立槽位，清空其中一个不会改变另一个。

### 运动平滑

- **关闭（默认，24 FPS）**：保留 H3 原始帧，不执行插帧，避免无需要时增加合成帧柔化和处理时间。
- **RIFE 2x（48 FPS）**：仅用于 RTX VSR 路线，按相邻帧逐对生成中间帧，N 帧输出为 `2N-1` 帧。编码帧率同步翻倍，所以视频时长、对白时间和音频内容都不变；检测到真正硬切时会旁路插值，避免合成跨镜头鬼影。

RIFE 逐对推理并只接入 RTX VSR；VOSR2 保持原始 24 FPS，避免先插帧再逐 2 帧重跑超分导致耗时翻倍而细节没有增加。启用前请从 [Comfy-Org 官方模型库](https://huggingface.co/Comfy-Org/frame_interpolation/resolve/main/frame_interpolation/rife_v4.26.safetensors) 下载 `rife_v4.26.safetensors`，放到 `ComfyUI/models/frame_interpolation/`；缺少模型会在 H3 采样前提示。训练型二采、VOSR2 和低显存预设关闭 RIFE，避免额外显存峰值；48 FPS 需要较多 CPU 内存缓存，8GB 级设备请使用低显存 + AI X2 路线并保持 24 FPS。

### 最终音频

- **自动增强响度（默认）**：最终编码前提升过小的 H3 音轨，峰值目标为 -1.5 dBFS，最多提升 30 dB；静音保持静音，源 AUDIO 不会被原地修改。
- **保持原始响度**：不处理 H3 解码音频，适合后续在剪辑软件中自行混音。

使用 RTX VSR 前，必须在当前 ComfyUI Python 中安装官方 `nvidia-vfx` wheel；以下 DaSiWa requirements 安装命令可保留为依赖安装入口：

```powershell
D:\ComfyUI_windows_portable-G313\python_embeded\python.exe -m pip install -r D:\ComfyUI_windows_portable-G313\ComfyUI\custom_nodes\ComfyUI-DaSiWa-Nodes\requirements.txt
```

Linux 请使用 NVIDIA VSR 支持驱动分支 `570.190+`、`580.82+` 或 `590.44+`，不要求安装 Windows NVIDIA Broadcast SDK。Windows 请检查 NVIDIA 驱动、官方 `nvidia-vfx` wheel 与 NVIDIA Broadcast SDK/Video Effects 运行库兼容。导演台会在 H3 开始前，以真实 `640×360 → 1280×720` 单帧执行一次 RTX VSR `load + run`；失败会提前停止，不会在视频生成后才报错。

切换模式或音色模式后，导演台会自动刷新可用预设。旧工作流如果保存了不适用的组合，会自动回退到“稳定质量”，并在警告输出中说明原因。

U11 的“运动平滑”使用流式 RIFE 路径，不调用会构造整段双倍帧批次的旧插帧链。训练型二采已内置到 `H3 训练型 3D Latent 二采（自动旁路）` 节点，用户只需选择性能预设，不需要手动连接分支；其他预设自动执行单采样路线。二采节点不再保留 VideoVAE 输入，也不会执行整段 VAE 解码、图像放大、再编码的高内存往返。

## 分辨率与排版

导演台的“生成规格”是唯一生效的视频时长、画面比例和最终输出目标分辨率入口。左侧 Settings 中原有的 `resolution_preset`、`aspect_preset_when_not_image` 和 `swap_aspect_when_not_image` 已移除，避免两边设置不一致。H3 原生时长支持 4-15 秒整数。比例包含横向 `3:2`、`4:3`、`8:5`、`16:9`、`21:9`，对应竖向比例、`1:1` 和 `CUSTOM`；普通档位宽高按 32 对齐，`768p H3`、`1080p FHD`、`2K QHD` 和 `4K UHD` 在 16:9 下保持精确的 1344×768、1920×1080、2560×1440、3840×2160（9:16 自动交换）。

这里的目标尺寸不是另一套需要手动配置的生成参数。低显存模式下，工作流自动执行 `H3 低分辨率采样 -> VAE 解码 -> 曝光保护 -> 选中的单一后处理 -> MP4 保存`；用户不需要连接节点。低显存 + AI 超分固定使用 X2，并一次处理一帧；超分节点找不到 X2 模型时会在采样前报错。2K/4K 与 SeedVR2/VOSR2 的显存峰值要按目标设备实际验证，不能仅凭最终视频尺寸判断所需显存。

“噪音种子”旁边可选择“固定、每次递增、每次递减、每次随机”。这是 ComfyUI 原生的生成后控制：当前任务使用当前显示的 seed，任务提交后再按所选模式准备下一次 seed。固定适合复现画面；递增/递减适合连续比较；随机适合批量探索。

U11 将主导演台、素材/路由、预览输出分为固定区域，上传槽保持两列规整排列，不需要手动连接图片或音频节点。导演台现有的快速设置、生成规格、导演与素材、音色参考、实际后端分区是稳定界面基线，后续功能优先在对应分区内扩展，不随意改变整体排列。


### 最终输出超分

新菜单提供三种最终超分：VOSR2、SeedVR2 和 AI 超分（低显存推荐）。默认选 VOSR2。AI 超分会使用已安装模型；低显存预设只接受 X2。缺少用户所选引擎依赖时，工作流会在 H3 开始前给出错误，避免静默替换路线。旧的 H3 latent 二采属于采样方案，不会出现在超分菜单中。

2K QHD 和 4K UHD 可选择任一显示的超分引擎；选择 VOSR2 时，工作流会按 VOSR2 路线处理，不会转交 SeedVR2。最终 4K 输出的显存、系统内存和耗时取决于采样方案、源尺寸、时长与所选引擎，建议先用短片实测。目前没有同素材的 AutoDL GPU 画质和耗时对照，单元测试只能验证路线和帧数，不能验证主观清晰度或显存峰值。
