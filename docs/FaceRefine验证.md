# FaceRefine 远程验证

日期：2026-09-15。硬件：RTX 5090，约 32GB 显存。

## 结果

本项目内置节点已在 ComfyUI 实际执行成功，但当前参数没有改善这段双人物近景的清晰度。
首帧、中间帧与末帧的右侧人脸对比显示：眼线、皮肤纹理更软，不能将运行成功等同于画质提升。
因此主 U11 示例已将整个人脸修复分支设为 Never/禁用。用户可以按需启用；左右人物后处理示例保留可运行状态。

## 输入与配置

- 原片：`193707_00001_audio.mp4`，1920×1080，24fps，158帧，约6.58秒。
- 跟踪：右侧黑衣人物，位置选择与连续跟踪，身份嵌入关闭；158帧均检测到人脸。
- 原裁剪倍率3.0导致画布缩小原裁剪至0.93～0.99倍；改为2.5后为1.12～1.19倍。
- H3画布768×768，8步，固定种子42，er_sde/simple，基础denoise=0.4。
- 逐帧倍率沿用0.35～1.0；此原片脸部较大，实际平均倍率0.35。
- 原图第一帧裁剪作为身份参考；混合INT8底模、INT4文本编码器、FL 8步v1.0 LoRA。

## 耗时与边界

- 初次仅跟踪任务：31.14秒，包含视频读取、检测、裁剪和预览写盘。
- 初次完整修复任务：207.34秒，源视频读取命中缓存；包括首次H3模型加载、跟踪、重绘、合成和输出。
- 输出仍为1920×1080、24fps、158帧。
- 最终音轨来自原片，不使用生成音轨。VHS重新编码音频，采样对齐部分相关系数约0.9996；
  第一次输出尾部少约32ms解码样本，不能宣称音频码流逐字节保留。
- 初次API验证的VHS动态编码参数未发送，采用CRF19；随后补传示例中的CRF16重新保存。
- CRF16仅重新保存耗时4.92秒，所有生成节点命中缓存；人脸偏软的观察未改变。
- 本次交付对照视频另外从原片复制音频码流，无重编码；视频本身不变。
  这一步是验证产物的后处理，VHS示例仍有上述音频重编码边界。
- 这些时间不是冷启动之外的稳定推理速度，也不能外推到4080、长视频或多人连续修复。
- 本次运行的是本项目右侧后处理示例；U11完整生成加修复链路已静态检查，未重新生成整段U11。

本次仅证明节点可用与该配方的实际表现。小脸、其他参考图、其他denoise参数仍需独立验证。
