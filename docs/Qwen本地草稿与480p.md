# Qwen 本地草稿与 480p

## 可选模型

作者模型页：https://huggingface.co/ethanfel/Qwen3-VL-32B-Ultra-Heretic-H3-ComfyUI-INT8-ConvRot

- `qwen3vl_32b_h3_ultra_uncensored_heretic_int8_convrot.safetensors`：H3 条件编码器，含语言层 0–49 和视觉编码器，约 24.55 GiB。可在原工作流 Checkpoint settings 的 CLIPLoader 中选择，类型为 `minimax`。这是生成视频的编码器；外层 FaceRefine 的 CLIPLoader 是另一条支路。
- `qwen3vl_32b_h3_generation_tail_50_63_int8_convrot.safetensors`：约 7.09 GiB，仅补充语言层 50–63、最终归一化和词表输出，用于本地文本生成。不能当作 CLIP 或视频底模使用。

两文件放入 `ComfyUI/models/text_encoders/`，也可放在其 H3 子目录；刷新后选择实际文件路径。项目不自动下载这两个大文件，也不把 INT8 编码器设为 8GB 默认值。作者使用 32GB 显存验证；8GB 加载、速度和峰值尚未验证。这不是人脸修复或声音克隆模型。

## 本地草稿

安装作者节点：https://github.com/ethanfel/ComfyUI-H3-Qwen3VL-TextGen

本次接口核对版本：`0d8504cafeeef15e5bcd4a8d85c089737f156bcd`。节点包无额外 pip 依赖，仍需兼容的 ComfyUI、PyTorch 和量化运行环境。本项目通过已注册的 `H3QwenVLGenerateText` 调用作者实现，复用其临时 Tail 卸载逻辑，不复制模型推理代码。

主工作流已移除「H3 本地提示词草稿」，构建工作流时也不再自动添加，避免产生无关的缺失节点提示。下面的说明仅适用于主动单独添加该可选节点的用户。启用后填写原始需求，选择两个文件，执行即可在节点下方看到草稿与报告。草稿、报告、原文也分别通过 STRING 输出。

先单独生成草稿并核对对白、Picture/Audio 编号和时序，再将满意的文本填入导演台。不要将未检查的草稿直接当作严格绑定保证。若仅测试草稿，请暂时停用视频输出节点，避免同次队列同时生成视频。它使用本地模型，不发送提示词到外部服务。

## 480p

在导演台的智能画质模式选择 `480p`。16:9 最终输出 854×480，9:16 为 480×854；其他比例保持短边 480，输出为偶数尺寸。采样尺寸对齐 32 像素，8GB 按现有时长预算限制网格。10 秒约 800×448，15 秒约 704×384，必要时执行单次 AI 放大到所选目标。不会自动升为 1080p，也不会自动执行训练型二采或 SeedVR2。

4–15 秒是允许提交的范围，不是全部模式已完成 8GB 实测或画质保证。480p 适合低负担预览，不会恢复已丢失的脸部细节。480p 功能独立于下面的 768p 二采修正。

## 213842 样片诊断

日志实际路线为 512×288 首采、768×448 二采、1344×768 最终输出。首采约 143 秒，latent 放大约 8 秒，分块二采约 553 秒，总耗时约 16 分钟。二采执行了十次四步分块采样。抽取 1、5、9 秒帧可见背景、头发和皮肤涂抹，不能仅以最终 768p 尺寸声称画质正常。

两阶段还同时加载四种额外社区 LoRA，影响尚未做同种子对照。新版示例关闭额外社区 LoRA，保留所需官方 Turbo；旧的用户保存工作流不会被覆盖，需自行把「H3 兼容加速模型路由」的 community_loras 改为「全部关闭」才能对照。

该日志只有 FaceRefine 跟踪记录，没有修复采样和合成记录。跟踪仅有一次有效人脸检测，脸高 17 像素，最长丢失 237 帧；这不能作为已完成修复的证据。当前结论基于日志、代码和输出抽帧；尚未生成修改后的 GPU 对照视频。

## 低显存 7–10 秒 768p 二采修正

此范围内的 1344×768 输出改为 672×384 首采、训练型 latent 2 倍放大、1344×768 分块二采，随后直接导出，不再把 768×448 二采结果交给逐帧 AI 放大。竖屏对称处理；非 64 对齐的目标使用略大的二采网格再小幅缩小。

第二阶段保留 512 像素空间分块、73 帧时间分块和现有显存不足重试。REF2VA 保留音频锁定与回填。此修正不改高显存路线、4–6 秒低显存 1080p 路线或 480p 路线，也不改 JSON 控件顺序或用户提示词；现有工作流在更新节点并重新启动 ComfyUI 后使用新计算。

新的首采和二采网格都更大，计算量增加，不能承诺提速；分块也不代表全部显存开销固定。8GB 峰值、耗时和清晰度改善仍需 GPU 样片验证。尺寸与接线回归通过不等于画质已验证。
