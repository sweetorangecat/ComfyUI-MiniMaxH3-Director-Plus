# 故障排查

## 克隆音色不像指定样本

按顺序排查：1) 样本是否在官方 2–15 秒区间——实测 5–10 秒干净单人声、无背景音乐、不削波时锁定最稳，插件会在 H3 生成前检查并报错/警告；2) 提示词是否把 `<Audio 1>` 明确绑定到角色对白（“橘总使用 <Audio 1> 的音色说：……”），只上传样本但不绑定会退化成通用音色；3) 是否用了少步数路线——极速 4 步/低显存 8 步是音色漂移的常见原因，改用“参考高清（原生20步）”；4) 文本编码器量化过重（如 int4）会削弱对参考绑定的理解，音色关键镜头建议 int8_convrot 或 bf16 文本编码器；5) H3 原生音色参考是软参考、不是严格声纹克隆，必须锁定本人声线时改用 Fish S2 高级锁定（填写目标对白 + 参考音频文本）。

## SeedVR2 视频超分报“依赖缺失”

`video_sr` 路线（以及“免费智能 1080p”的 SeedVR2 优先逻辑）需要两个条件同时满足：已安装 ComfyUI-SeedVR2_VideoUpscaler 自定义节点，且 `ComfyUI/models/SEEDVR2/` 内存在 `seedvr2_ema_3b` DiT 权重（fp8 或 Q4_K_M GGUF）与 `ema_vae_fp16.safetensors`。任一缺失都会在 H3 生成前报错并列出缺项，不会静默改用其他超分。8GB 级显卡会自动选择 Q4_K_M + block swap 32 + VAE 分块 + 每批 5 帧的最省显存档位；若仍然爆显存，请改用通用 AI 超分（`RealESRGAN_x2plus.pth` 或 `4x-UltraSharpV2.safetensors`）。

## 显示“模型未就绪”

先看 `/h3-director-plus/status`。Fish S2 需要 `ComfyUI-fish-audio-s2` 节点和 `models/fishaudioS2/` 下的实际模型文件；只有节点目录不能生成。H3 则检查 `models/diffusion_models/` 下的 FL2VA/REF2VA 文件名是否被 ComfyUI 扫描到。

## I2VA/FL2VA 带音色后画面变了

这是设计行为：音色参考会切换到 `ref2va_model`，首尾图片从硬端点改为提示词级 reference。页面的“实际后端”会显示当前路由。若必须严格锁死首尾帧，选择“不使用音色”，保持 `fl2va_model`。

## 4 步结果不稳定

“极速4步”对 T2VA/FL2VA/I2VA/L2VA 加载官方 H3 Turbo LoRA，REF2VA/音色参考加载官方 Ref2VA Turbo。确认状态中对应 LoRA 可用，并先用“稳定质量”确认构图，再切换 4 步。

## 3070 8GB 低显存模式仍然 OOM

“免费智能 1080p”在低显存设备上会切换到受限路线：低显存二采最多 6 秒，并要求至少 6GB 空闲显存；这里的空闲显存是任务开始前的即时值，不是显卡标称总容量。生成阶段分辨率不等于最终输出分辨率，缺少 `RealESRGAN_x2plus.pth` 时应在排队前明确报错，不会静默降级到其他模型。

U11 的“低显存”会在本次执行期间临时启用 ComfyUI 的 LOW_VRAM 状态，并保留原生动态 patcher 路由：约 15GB 的 Qwen3VL 文本编码器和视频/音频 VAE 仍放在主机内存分层管理，当前计算所需权重才进入 GPU。不要把包装器强制改成 CPU，否则文本编码会长时间停滞。采样结束后会恢复原状态。

普通低显存模式会按视频时长限制 H3 原生采样：4/6/8/10/12/15 秒约为 1.00/0.65/0.50/0.36/0.30/0.26 MP，支持 4–15 秒但不执行训练型二采，最终只开放到 1080p。需要真二采时选择单独的“低显存二采”：1080p 支持 4–6 秒和 FHD 像素预算。4 秒约 0.46MP 首采/1.03MP 神经二采；5/6 秒约 0.37/0.31MP 首采，按时长换空间以控制 8GB 峰值，再由单一 `RealESRGAN_x2plus.pth` 逐帧重建到 1080p。日志应出现 `postprocess_path=ai_upscale`，不再出现最终 RTX VSR。开始前必须至少有 6.0GB CUDA 空闲显存。超过边界会立即报错，不应删除检查后硬跑。参考图数量、其他常驻模型和 `--reserve-vram` 仍会影响余量。

“质量优先加速”同样会启用 LOW_VRAM 动态分层，但保持 20 步和原生画质路线。它不会把 H3 的时序激活、视频 VAE 解码和最终帧缓存变小；因此 32GB 显存也不保证直接执行 1.75MP + 15 秒。若仍 OOM，改用“质量优先二采样”，由约 0.9MP 首采、训练型 1.5 倍 latent 放大和低 sigma 二采构建细节基准。注意训练型放大器节省的是首采时间，不会消除第二阶段的高分辨率采样峰值；U11 会要求 15 秒任务至少保留约 24GB 可用显存，并在开始前拒绝显存已被其他任务占用的组合。

## 质量二采提示缺少节点或模型

`MinimaxH3LatentUpscaler3D` / `minimax_h3_latent_upscaler_3d_bf16.safetensors` 缺失时，安装或更新 `LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler`，模型放到 `models/latent_upscale_models/`。FL 路线还必须同时存在 8 步 v1.0 与 4 步 768p v1.1 LoRA；Reference 路线必须存在 turbo v4 LoRA（`minimax_h3_turbo_v4_step600_ema.safetensors` 或其 pruned ComfyUI 转换版，二选一）。旧配方依赖的 `H3SigmaRefiner` 与 Ref2V 4 步 LoRA 已停用，仅用于旧工作流迁移识别，不再要求安装。不要把 v1.0 768p 文件改名冒充 v1.1，依赖检查按精确文件名执行。

如果 AutoDL 无法使用 `git`，请按《使用说明》的 `codeload.github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler` ZIP 命令安装节点，并用 `hf download LBH-123-AI/Minimax_h3_latent_Upscaler` 下载模型。

## 二采出现灰屏、噪点、重影或跳帧

先确认任务元数据中的 `resolved_two_stage_route`、`first_stage_width/height`、`second_stage_width/height` 和 `postprocess_path`。新版质量二采不应出现“6+2”“bilinear”或 RIFE：FL 必须为 `trained_latent_fl`，Reference 必须为 `trained_latent_ref`，运动平滑必须关闭。第二阶段路径看 `two_stage_second_stage_path`：`mmh3_split_upscale` 表示走了分块采样（正常且更省显存），`full_frame` 表示未检测到 `MMH3SplitUpscale` 或 guide 关闭了分块。若服务端仍执行旧标题 `H3 专用 Latent 二采`，说明旧 U11 JSON 或旧自定义节点还在缓存中；更新节点、重启 ComfyUI，并重新导入唯一的 U11 工作流。不要只刷新浏览器页面后继续复用旧队列。

28GB+ 显卡执行精确 1080p FHD 的质量二采时，导演日志应显示 `native=1344x768 target=1920x1080 postprocess=balanced_fhd_downscale`，后续二采日志应显示 `2016x1152`。这条链路不应出现 RTX VSR 前置检查；若仍显示 `1280x704 -> 1920x1056 -> RTX VSR`，说明服务器仍在运行旧提交。2K/4K 出现 RTX VSR 是正常路线，不要按 FHD 日志判断。

错误中的“安全余量 24GB”指当前任务启动前的空闲显存，不是显卡总容量。20–24GB 级显卡或刚取消任务后只剩 21.2GB 空闲显存的 32GB 显卡，精确 FHD 会改走 `1280x704 -> 1920x1056 -> 1920x1080` 的保守路线；至少需要 18GB 空闲显存。若取消任务后低于 18GB，先等待旧模型卸载或重启 ComfyUI，再重新排队。

## SeedVR2 视频超分阶段显存不足（Phase 3 VAE decoding）

32GB 级显卡在 H3 采样完成后进入 SeedVR2 时，ComfyUI 的模型缓存仍驻留着约 20–25GB 的 H3 DiT/文本编码器/VAE——ComfyUI 看不见 SeedVR2 自己的 runner，不会主动让位；叠加 1080p+ 竖屏未分块 VAE 解码单块 2.5GB+ 的峰值就会 OOM。自修复版本起，视频超分开始前会自动卸载全部 ComfyUI 常驻模型并清空缓存，且所有显存档位的 VAE 解码都改为分块进行；日志中不应再出现 Phase 3 的连续 OOM-retry。若更新后仍在此处 OOM，请确认插件已更新并重启 ComfyUI，再重跑任务。

## 生成的嗓音与上传的音色样本不符

先看导演日志的 `ref_audios=`：如果是 `ref_audios=0`，说明音色样本根本没有进入模型。最常见的原因是**音色模式停在"不使用音色"**——此时上传的音色音频会被忽略（新版本会明确告警），提示词里的 `<Audio 1>` 失去绑定对象，H3 只能按文字描述凭空生成嗓音（角色是猫时容易出尖细卡通音）。正确做法：音色模式切换为"H3 原生参考"或"Fish S2 声纹锁定"，把样本传到音色参考 1，并在提示词里用 `<Audio 1>` 绑定到具体角色的对白；样本按官方窗口取 2–15 秒、以 5–10 秒干净单人语音最佳。自修复版本起，提示词含 `<Audio N>` 但没有任何绑定音频时，任务会在排队前直接报错，不会再空跑几十分钟。注意 H3 原生参考只约束性别/音域，要高度还原本人声线请用 Fish S2 路线。

## 质量二采的 RTX 前置检查失败

质量二采会在 H3 前验证 `HIGHBITRATE_ULTRA` VSR，并只执行一次 RTX VSR。`DEBLUR_LOW` 双效果链已停用；如果旧工作流带有该标记，导演台会强制旁路，避免 NVIDIA 去模糊输出造成彩条、花屏或伪影。VSR 依赖、驱动或运行库失败都会在 H3 前终止，不能静默回退为普通缩放。

## 上传失败或路径错误

上传接口只接受单层文件名和常用图片/视频/音频扩展名。不要提交绝对路径、`../`、反斜杠目录或不支持的扩展名。上传成功后使用返回的 `h3-director-plus/...` 相对路径。

导演台的“移除”不是删除文件：它只清空隐藏节点引用、调用 widget callback、刷新预览并标记画布 dirty，原文件仍保留在 ComfyUI 的 input 目录。REF2VA 删除中间图片后会重新编号并提示检查 `<Picture N>`；音频会与角色名一起重新编号并提示检查 `<Audio N>`。首帧和尾帧槽位在非 REF2VA 模式下独立清空。

如果工作流在另一台机器（如 AutoDL）保存过，或 input 目录里的素材后来被删除，新版 ComfyUI 前端会把这些失效引用当成“缺少输入 / 无效输入”并阻止运行——即使当前是 T2VA 等根本不需要图片的模式。导演台现在会在每次渲染时自动清除这类指向不存在文件的引用，并在素材区提示已清除的数量；失效素材需要时重新上传即可。

## 节点重叠或旧工作流异常

只打开 U11 新文件，不要覆盖 U10。运行 `tools/validate_workflow.py` 可检查重复 ID、断链、子图端点和可见节点重叠。U11 的额外参考图在下方第二行；Fish S2 是折叠且静音的可选节点。
