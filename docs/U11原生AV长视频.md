最新实测状态：既有隔离实验的完整 90 秒原生样例与最终 2K 文件均已装配。最终文件为 2160 帧、24 FPS、90 秒、2560×1440 精确 16:9，已按 `assembled-2k/complete_content_review.json` 的范围完成全文件解码、精确 PTS/音轨、抽样视觉与八个实际接缝审查，并交付用户副本（SHA256 `54b74fc26269f70fb9a9cf0fe234ceb72ed111b5bfd645186ea1ba9038556993`）。九窗保持原 VOSR2 `manual_baseline`；早餐软 mask 返修、晚安相位与空手结尾按回执接受。该审查是抽样画面证据，未认证亲耳听验、声纹、受控短片感知等质或无限续拍稳定性；新 U11 生产入口未部署、未完成 GPU 验收。证据根目录：`outputs/diagnostics/long_video_trial_20261112/nangongwan90/`。以下时间线保留当时的失败与未完成状态。

下方按时间保留失败、撤回和候选记录；当前状态以本总览及最后的完整原生样例验收章节为准，不将旧失败回执回写为通过。

该分支在原 U11 的“预览与输出”增加原生长视频入口。“长视频（按需开启）”默认关闭；原来的短片参数、素材上传、音色与输出行为保留。

打开原来的 U11 JSON，在“长视频（按需开启）”中开启，点击 **30 / 60 / 90 秒**或输入自定义有限总秒数，填写项目名，导入 H3 技能的 **U11 单语 scene_contract JSON**（也可展开粘贴）。总时长与合同不同会明确提示；“采用剧情时长”是独立操作，不会拉伸剧情或删台词。默认 `{}` 不能运行，丰富的 `source_beats` 规划包需要先由技能导出。

原 U11 默认短片设置是 FL2VA / 智能画质。需要时明确点击一次“应用长片推荐设置”，应用 REF2VA、质量优先二采样、SelfLift、VOSR2 `manual_baseline` 并关闭修脸/插帧；不改变原音色、种子、画幅、素材、模型或编码选择。点击“预检剧情 / 实际接线（不排队）”，检查总时长、全部窗口、真实参考绑定、来源待审标记及解析后的完整文件编码，再使用原 ComfyUI 普通排队。预检不加载模型、不哈希资产、不建 take、不授予资产/画面审批。支持无参考音色或实际原 H3 参考音色；缺少合同要求的参考时不会发明替代音色。

合同 schema 见 `templates/u11_long_video_contract.schema.json`；规范见 [U11 长视频合同接口](U11长视频合同接口.md)。仓库 `examples/u11_long_video_scene_contract.en.json` 和 `.zh.json` 是实际安装版技能的九窗 90 秒导出数据，保留 `not_ready_for_video: true` 与各资产的 `approved:false/mounted:false`，仅供互通对照，不是另一份工作流或已审批故事。帧号为 24 FPS 全局位置；完整对白和不可拆分动作不会跨越交接。逐窗当前相位、参考选择和音色策略仍要核对原 U11 实际绑定。

进度区分别显示目标、连续已确认时长和已生成候选；下拉框可以选择以前接受的窗口。轮询保留审查草稿、当前窗口和播放位置。每窗保存 clean AV、技术校验和原生预览后等待实际审查，填写实际尾态与检查范围。接缝区定位实际不可变父源最后交付帧与子窗首批净新增帧，并可按需生成小幅 CPU 对照图；完整预览含保护历史和生成余量，不能混同交付范围。相等的 latent 前缀不能授予可见连续性审批。

若下一窗确实要借用父源未交付尾部，面板显示必要的“衔接素材审查”，按实际预览来源秒段检查动作/声音并记录真实自由起点状态；已有交付审批不会自动批准余量。证明缺失会阻止增强与下一窗。坏尾部可在实际父窗明确选择“整窗重新生成（后续需重做，保留旧文件）”。一般返修在成片秒数中选择起止，默认只改视频并锁音频；显示服务器实际向外对齐的秒段与 VAE 时间耦合限制。请求碰到受保护衔接素材时明确要求修正父来源，不会偷偷裁掉坏内容。高级双流/软权重保留在 API 中，不要求普通用户输入 latent 索引。

局部返修的范围会在撤销来源前检查；无效范围不会破坏已有检查点。返修执行失败后，“继续”仍保留原先的锁音频和开放范围，也可以选择“放弃本次局部返修，重新生成本窗”。续窗的返修来源必须与当前父窗的受保护视频和音频历史完全一致。

“停止续拍”保留正在执行窗口的检查点，完成该窗后停止提交后续任务。“继续”从有效检查点恢复。解码或预览失败可以从 clean AV 重试，无须重跑已经保存的采样。修改最终尺寸或增强设置，会复用仍有效的原生窗口；修改模型、参考文件、生成配置或真实父历史，则撤销受影响来源。文件与审查记录均带哈希，不能靠替换同名文件继续旧项目。

自动加载的 SelfLift、动作 LoRA 和 VOSR2 权重也分别进入生成或增强指纹；新安装更优先的候选模型会要求重新核对项目。同名权重替换后，加载器的输出缓存和实例缓存都会更新，普通续窗保留相同加载器身份。最终成片绑定实际接受的来源链；装配期间返修会阻止旧来源发布为新结果。

目标可以是 30、60、120 秒或其他有限时长，实际交付时长按 24 FPS 舍入后显示。增加剧情和目标长度，再用同一项目名排队，会保留输入未变的完整前段；原来不足一窗的末段可能需要重新生成。`manual` 表示到当前已编排剧情的结尾暂停，补充剧情后可继续延长；它不会自动编造后续剧情或无休止占用 GPU。

项目保存在 `output/h3_native_av/<项目名>/`，逐窗落盘，装配时按文件读取连续净新增帧和累计音频采样范围。最终文件名包含项目种子，实际逐窗种子及重试保存在项目记录中。不会用跳帧、改速、补帧、冻结画面或插镜掩盖生成缺陷。中间增强 MP4 的音轨可能受外部编码器毫秒时钟舍入影响，回执明确记录该差值；完整成片从原生交付 WAV 重新装配，按精确采样时钟验证音轨。

本轮完整成片支持 **H.264 / MP4 / 8-bit / AAC**；Auto 明确解析为这些值。其他 codec/container/10-bit/audio codec 在资产哈希和昂贵生成前报错，不静默降级。CRF 使用原二采质量策略 `min(原 quality,16)`，音频遵循所选 64k–320k；实际配方进入导出指纹和装配报告。RGB→YUV 使用显式 BT.709 矩阵、full→limited 范围转换及对应标签。增强/装配代码变化时要求重新排队原 U11 刷新导出配方，保留仍有效的原生窗口。可选 CPU 依赖见 `requirements-long-video.txt`，不会自动安装或下载。
