# H3 真人质感：实测结果和未通过的候选

日期：2026-11-14。用户实际反馈：双人动作成片明显失去原主脸参考的真人感。本记录保留负面结果，防止把“执行成功”“更快”或局部肖像当作整片画质通过。

## 测试范围

- 实际设备报告为 RTX 4080 SUPER、32760MiB，不能写成5090测速。
- 正式片为15秒双人走廊抓腕/解脱，有克隆音色和无音色两条作者配方对照；seed均为9685887441。三条成片均未通过真人质感验收。
- 定位阶段主要使用4秒请求，实际107帧、24FPS、1344×768原生画面，绕过超分和ColorGuard。每组保存输入、提交图、prompt_id、日志起点、原生PNG、媒体文件及检查结论。
- 静态VAE控制、单人近景、全身动作和两人中景是不同任务。不能把它们混为单变量对照，也不能把4秒无对白结果外推到15秒克隆音色或长片。
- 图片和原始生成记录归档于用户本地制作项目，没有把人物素材、音色和视频纳入Git。

## 已定位并修复的超分错误

远程实际Linux兼容层在`_venc_features`内将RGB乘255后直接裁到0..1，丢失大部分颜色变化。上游[VOSR推理代码](https://github.com/cswry/VOSR/blob/main/inference_vosr_onestep.py)在裁剪前恢复RGB0..1，随后执行特征网络规范化。

提交`d2839f9`修正已检查的兼容源码，并保留原512分块、模型、种子、颜色对齐和几何规则。2397项Python回归通过，本地安装补丁测试15项通过。远程69个发布文件与修正后引擎一致、服务已重启，实际生产收尾节点三帧执行成功。

修正后兼容引擎SHA256：`3a91cc576bdbeb65c4818434e39661fc48e8c9563046d0a601ac3e20be3f2c71`。此源码修正没有套用到Windows原生编译TE实现。

同近景原帧的短对照可见更多皮肤表面变化，仍有平滑皮肤和头发刻线感。它是确定的错误修复，**不是完整影片真人感已恢复的证据**。

## 生成阶段对照

超分前已有平滑皮肤和成束头发；作者配方的无音色版本也存在。以下候选均没有被设为新的生产默认：

| 候选 | 观察 | 决策 |
| --- | --- | --- |
| 原链路单张主脸近景 | 保留较好的肤色变化和细发丝，但有裁顶/表演偏差 | 只作正对照，整片不通过 |
| 同近景恢复原四张参考 | 仍保留较好近景质感 | 不把参考张数单独认作根因 |
| 全身SelfLift首轮0.6→0.8 | 未见有说服力的真人感改善 | 不增大首轮默认 |
| 全身纯Ref、无加速LoRA、原生20步 | 皮肤/发丝仍弱，任务719.822秒 | 不用更多步数冒充修复 |
| 全身纯Ref、匹配官方8步 | 更短的单次耗时，真人感仍未通过 | 不宣称画质通过 |
| 中景、主脸加新场景两张参考 | 脸更清楚，仍偏平滑/刻线 | 新资产只作诊断 |
| 同中景、同模型，仅去Mystic | 细纹/颗粒更明显，未恢复真人感 | 不删除默认Mystic |
| 同中景、同混合底模，原生20步 | 更柔和，仍未恢复原主脸微纹理，611.932秒 | 不改20步默认 |

这些结果排除了几种简单修复，尚未确定唯一的生成端原因。景别与面部有效像素、参考图本身的质感、条件约束方式和生成配方都可能参与；不能从单个消融得出某项技术在所有场景均无效。

## 原生开场引导：配对负面结果

基线`medium_ref8_control`：`34fe480c-10e0-49e6-83c3-68754e546a13`。

引导组`medium_ref8_start_guide`：`3d03f812-64a9-465c-9d18-aef83e1457ff`。

两组使用相同纯Ref底模、官方Ref8 v1.0、主脸及已检查的新场景图、提示词、seed、4秒动作。接线差异只包括从同一场景图增加`MiniMaxH3AddGuide(frame_idx=0)`、消费其conditioning及输出文件名，已进行图结构等同性检查。

两组107帧完整解码及逐帧PTS通过；实际查看0/48/106原帧，另查看引导组每半秒概览。引导没有明显恢复皮肤/发丝细节，结尾增加参考图中没有的暖黄色底边光晕，解脱也偏晚，因此不采用为真人质感修复。

总耗时204.352/168.689秒，第二组缓存更多节点；实际采样约112.56/120.16秒，不能宣称引导提速。[原生文档](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)将AddGuide定义为条件引导；本次没有把它当作像素复制或视频重绘。

## 超分VAE分块：只得到局部速度证据

相同三张原生RGB8近景帧，各重复为两帧物理批次，排除预热，以1024→1280→1280→1024顺序测试。固定1920×1098画布、种子、修正后的实际引擎、DiT512、重叠、批量与颜色对齐，仅改变VAE tile。

每对帧均值5.188/3.834秒，重建阶段少约26.1%；独立进程峰值allocated5.657/6.025GiB。已查看同帧0两档，以及1280的48/106帧，外观很相近，仍有平滑/刻线感，没有明显新增接缝。只查看了一组匹配帧对，没有连续整片时序验收，因此没有修改生产档位，也没有宣称端到端提速26%、低显存通过或皮肤已修复。
