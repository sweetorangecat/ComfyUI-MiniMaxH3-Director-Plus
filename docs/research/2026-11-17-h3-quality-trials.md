## IC 配方的兼容性发现

最初照社区 API 图，用普通 LoRA Loader 叠 HyperFlow → LMS → IC，完整 REF INT8 底模在 AdaLN 层报形状错误。这条测试被主动中断，不能用它的输出评价 IC。已留存 `jobs/ic-no-clone8/` 的执行报告。

实际检查 LMS 文件头：50 个 AdaLN 分支的 A 为 `[64,8]`，B 为 `[96768,64]`；完整 REF 底模对应投影为 `[96768,2688]`。这些分支依赖独立的 8 维时间曲线，不能按普通权重增量直接 reshape 到完整底模。

上游 IC `54a7104b` 的 `infer/ref2va_ic/sharp.py` 已明确实现：完整投影输出加上 `B(A(curve(t)))`。`hyperflow.py` 还使用端点时间嵌入，`emb_t + 0.25 × (emb_r - emb_t)`。本机现有 Comfy HyperFlow 转换文件的元数据明确列出端点层被省略。仅加载转换 LoRA 不能称完整复现了原作者时序逻辑。

隔离测试增加了 `TrialICRecipe` 桥接：

1. 保留完整 REF 底模、208 个普通 LMS 模块及全部 50 个曲线分支。
2. 用上游声明的 REF 曲线，原始 tensor 字节 SHA256 必须是 `c02a6c11888297688c1e6278185ea1f947023acfc69f9003bbcdcec9a229a8e7`。
3. 从原始 HyperFlow 权重精确读取四个端点矩阵，端点基底使用未加载 LoRA 的原始完整 REF 时间嵌入权重。
4. 使用原 up3 网格、Euler、CFG1、12/3 shifts、IC 强度 1；按实际 distinct timestep 行设置下一步端点。曲线分支仍按原始 t 取值。

CPU 数值验证已经执行：对上游原函数与真实 LMS 权重，曲线插值、三个端点网格、当前 Comfy 时间嵌入和一个真实曲线分支的最大绝对差均为 **0**。完整 50 个分支数量已检查。证据：`ic-recipe-validation.stdout.txt`。这证明组件计算一致，**不证明视频质量、动作或速度已达标**。

## IC 实际运行方式与边界

为了释放大文本编码器的 CPU 缓存，先保存精确 conditioning 与复合 latent，再只重启隔离 Comfy 进行重建。文件带 SHA256，加载前复核。预处理实跑 133.492444 秒；重建与解码时间须另外实测，再交代两阶段总成本。模型下载、失败重试和兼容开发耗时不冒充推理速度。

IC LoRA SHA256：`a0c93dce50d9034cc084073b6c095d09ff25ad02351ac4d4f10113d67ae64ab3`。完整 REF INT8 convrot、HyperFlow8、LMS Sharp r64、IC，3D latent upscaler 1.5 倍，目标 2016×1152，192 帧，seed42。隔离 Comfy 使用已验证可导入的 FlashAttention 2.8.3。

当前实现仍属于适配测试：使用标准 H3 FP16 视频 VAE 解码，尚未复现作者 Fast VAE；Comfy 内部的固定音频行与上游独立管线的精确标记也有边界差异。最终音轨直接拷贝原草稿，仍需检查重建后的嘴形。

## FlashVSR+ 测试设置

代码固定 `b515ffc6dba57fdc9ad84c66cadd87d05f27590a`，模型 revision 固定 `46b79520946ac67dec94d1566490690953c7debc`，Turbo、BF16、官方 Triton attention、temporal compression4、decode_every28。每个模型文件完成后验证完整 SHA256。

官方预处理会 center-crop。测试只替换 IO 边界：原画面精确缩放到 2016×1152，左右各反射补 16px，送入 2048×1152 的 128 对齐画布；模型计算不改，输出去掉同样补边，再保存。使用 RGB、CRF16、相同原音轨，留存编码前 PNG。

根盘空间不足以同时存两组新权重，Flash 权重暂放自己创建的共享内存目录。大文本编码阶段和重建阶段分进程，避免与临时权重共占内存。不得删除用户已有模型或输出腾空间。

### 媒体与画面检查边界

`media-verification.json`已完整解码五条输出（IC8、Flash8/tc4、同源VOSR2/8、Flash8/tc2、Flash15克隆），核对逐帧24fps精确PTS、192/360帧、8/15秒、2016×1152与原7:4画幅。全部8秒输出的251个AAC packet、15秒输出的470个AAC packet逐包哈希均与相应原片一致。它证明后处理没改变现有音轨，不证明原H3克隆音色本身完全合格，也不替代嘴形判断。

`both-comparison`、`clone15-comparison`含同步全景与100%面部裁切、描述性颜色记录以及同步对比MP4。检查了无克隆f24/96/180与克隆f72/192/336的100%脸部；无克隆连续帧18–25、29–36的脸与18–25的手部已人工审图。这些图中Flash保留大体表演，IC有较明显的重绘差异。审图范围继续在证据表中追加；本工具环境没有直接连续视频感知接口，不能把生成了对比MP4或看了几张帧图写成已完整播放验收。

另检查无克隆102–109、108–115的连续脸部及29–36、108–115的手部，覆盖首个解码分段边界；克隆66–73、220–227、332–339的连续脸部与214–221的手部，覆盖讲话、转头及后两个分段附近。精确已审清单在`visual-review.json`，不将未审页面列为已通过。当前采样范围未见明显新增大幅动作改写，仍不能排除快速运动中的闪烁或细微嘴形变化。

### 补充同源VOSR2基线

原留存VOSR2来自未编码原帧且尺寸较小，因此新增一个正式基线：相同`native.mp4`、192帧、先bicubic到2016×1152、现有`MiniMaxH3VideoFinish`+`manual_baseline`执行1x恢复、相同CRF16/yuv420p、最终直接copy原AAC。VOSR2 seed沿用原111731200。Flash seed1、IC seed42沿各自配方，不同模型的同seed本来也不代表相同噪声轨迹。

此基线通过原服务6006的现有节点执行，只提交一条独立诊断任务，不改运行代码、UI或默认。实际完成耗时736.869132秒，约12分17秒；其中VOSR2重建（含模型释放/加载/设置/处理/cleanup）708.964923秒，整个finish710.306025秒，mux0.139870秒。其余含读取、bicubic、保存无损取证帧及编码；总时间包含最多约10秒轮询等待。当前实际配置`image_batch=4`、`frame_batch=2`、wavelet、staged、512/32瓦片；不是未启用空间批处理的慢基线。VOSR2 allocator峰值allocated5.67GiB/reserved6.875GiB，Flash速度收益伴随更高的显存占用。

相同草稿与2016×1152输出，VOSR2完整诊断736.87秒与Flash134.78秒相比约5.47倍；重建范围708.96秒与Flash推理+编码+mux119.28秒相比约5.94倍，但两者范围不完全一致。各后端自身预处理、编码preset和取证帧保存数仍不同，因此这些是本次具体执行的墙钟成本，不能宣称严格独立模型算子倍数，更不能称整条H3生成也快了5倍。

同源VOSR2成片SHA256：`b07085c771a643a63decf533545d939ea53233fdd5f955bf325f7dc1fbd32c61`。对照证据在`same-input-comparison`。完成后对空队列原服务调用`/free`释放本次大IMAGE缓存，保留服务与所有媒体文件，避免后续Flash测试与已完成基线的缓存挤占内存。

同源基线f0/24/96脸部100%对照已审：VOSR2同样显著锐化头发与衣服，脸部仍偏抛光平滑；Flash不是一个已证明恢复真实皮肤的胜出者。同源VOSR2相对草稿整帧均值亮度约−0.99/255、饱和度约+0.00068，这与来自未编码原帧的旧留存对照不同，不能混为同一次处理。

无克隆0–7连续帧检查发现，tc4首帧眼睑开合与草稿不完全一致。随后完成相同输入、模型、seed、尺寸和编解码设置，仅`temporal_compression=4→2`的复测。实际完整耗时216.785414秒，约3分37秒，比tc4增加约61%；其中加载13.298615秒、推理+编码+mux201.168115秒。成片192帧、2016×1152，SHA256：`47e1f5dc26983f9fb22bb2a0b389619be0e5c18fff0607de3b05e08a280d682d`。

首帧编码前PNG四路对比`tc2-first-frame.png`已审：tc2仍有眼睑开合差异，皮肤仍平滑，未修复所追查的问题。tc4主要动作保持不等于微表情逐帧完全保留，增加时间采样密度本身不保证去除生成重绘。同帧/连续帧证据在`tc2-comparison`、`tc2-motion-sheets`，本轮不再扩展tc2到15秒。

tc2的0–7、29–36、50–57、106–113连续脸部已检查，包含讲话和其55帧/111帧附近的解码分段交界，没有建立足够的皮肤质感收益。它通过媒体完整性检查，但不通过本任务的照片级质感目标。精确清单仍以`visual-review.json`为准。
